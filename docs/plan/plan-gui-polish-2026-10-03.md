# GUI 打磨：审查结论与三阶段实施计划

> 状态：只读审查已完成；第一阶段 F1–F5 已实现，IDEA 检查及双平台构建已通过。第二阶段页面重排、第三阶段游戏内验收尚未完成。
> 日期：2026-10-03；源码基线：`403f763`；审查开始时 Git 工作区干净。
> 用户已确认：分为功能修复、页面重排、游戏内验收三个阶段；保留 Minecraft 像素风，优化层级、间距、文案与空间利用；研究按类型组织规则树。允许大范围调整排版。

## 1. 目标与范围

玩家应能完成“找到规则 → 看懂输入、触发与产出 → 编辑 → 查看待应用改动 → 应用”的完整流程。首先修复无法编辑、交互丢失、错误摘要和内容越界，再优化页面。

沿用现有规则 JSON、客户端草稿、撤销、目录、服务端权威保存、覆盖层与独占会话。分类树是客户端视图，不对应磁盘目录，不新增规则分类字段。第三方未知字段和类型原样保留；只读状态也必须能查看内容。

本计划细化并调整现有 GUI 计划的显示和交互方案，不宣称原有实现已经通过游戏内验收。数量演算、后端结算机制调整、独立 kit 发布不属于本轮范围。

## 4. 页面结构与像素风方向

保留现有灰色原版面板、像素边框、物品槽、灰蓝选中与主要操作色。通过区域底色、分隔、标题与留白建立层级；状态同时用文字/图标表达。正常只读信息保持可读，禁用操作与辅助信息不要混用。

### 4.1 规则管理：类型树 + 选中预览

宽度足够时：顶部搜索/状态筛选；左侧规则树；右侧选中规则的简短预览。顶部放“新建”和“模板”；选中规则的操作放预览内；低频和危险操作放“更多”；底部固定放待应用数量与“应用更改”。

```text
规则管理                 [搜索规则…] [状态]   [新建] [模板]
┌ 类型树 ─────────┬ 选中规则 ─────────────────────┐
│ ▾ 物品 (5)      │ 鸡肉腐化      已启用 · 内置   │
│   鸡肉腐化      │ [鸡肉图标] 鸡肉 → 腐肉       │
│   雷暴凝水      │ 自然消失 · 300 秒 · 每组消耗 1│
│ ▸ 方块 (2)      │ 条件：不限制                 │
│ ▸ 生物 (1)      │ [编辑] [启用/停用] [更多]    │
│ ▸ 组合规则 (3)  │ ID / 来源 / 详细说明：展开    │
└─────────────────┴──────────────────────────────┘
待应用：2 条规则                         [应用更改]
```

分组规则：

1. 主分组按可见产出类别：物品、方块、生物、经验、战利品、世界事件、组合规则、扩展/其他、未完成。
2. 在所有候选中收集产出类型；消耗源、催化剂和流体不参与主分类。同类多个效果仍归同组，多个产出类别归“组合规则”。仅含消耗效果的规则归“其他”，未知类型保留可识别提示，无法判定时归“扩展/其他”。
3. 每条规则只出现一次。来源、启用、问题与草稿作为状态和筛选，不重复制造目录层级。实际 JSON 错误导致无法分类时给出明确问题状态。
4. 搜索名称、自动标题、规则 ID 和源/结果 ID；已有名称缓存时也搜索物品名。命中后展示祖先分组并临时展开，清空搜索恢复之前折叠状态。
5. 以稳定 ID 维护选择和折叠状态。分类依据当前草稿，改效果后可以重新归组，但保持当前规则定位；应用成功后使用新快照。
6. 复用 UiTreeView，分组节点只负责展开，叶节点单击预览、双击/Enter 编辑。空列表、无搜索结果、快照加载中、只有问题条目分别显示明确状态。

窄窗口不强塞左右两栏：规则树占内容区，选中预览可展开，进入编辑后使用完整内容宽度。不要通过缩小字体解决空间不足。

### 4.2 规则编辑：按玩家操作分区

保留四个自由切换页面，缩短为“基本 / 输入 / 触发 / 结果”。顶部主要显示名称、状态和未应用标记，技术 ID 放展开详情。底部只保留固定长度的“返回 / 撤销 / 重做 / 应用更改”，撤销具体操作放 tooltip 或状态提示。

| 页面 | 常见内容 | 收起或进入详情的内容 |
|---|---|---|
| 基本 | 名称、启用、自动命名入口 | 优先级、备注、ID、结构版本；备注提供完整、多行查看/编辑 |
| 输入 | 已选物品图标与名称、添加/移除、每组消耗；有催化剂时展示催化剂区 | 排除物品、标签详情、消耗效果绑定来源说明 |
| 触发 | 消失方式的紧凑选项；选择自然时显示等待秒数；条件列表与“添加条件” | 嵌套分组、取反和条件参数进入独立条件编辑区，避免永久占一个大空框 |
| 结果 | 默认“结果 1”；当前结果的效果列表；添加效果；选中效果的参数 | 单结果时不展示无意义的结果选取方式；添加第二结果后显示“轮流 / 按顺序”；高级策略按相关类型展示 |

结果页宽度充足时，结果/效果导航与参数详情并排；窄窗口先选结果/效果，再进入参数详情，有明确返回路径。新增效果后直接定位到必填参数。一个简单“鸡肉 → 腐肉”规则应直接让玩家看到“产出：腐肉，数量：1”。

单结果内部继续保留 effects/outcomes 的原始形态，界面不要求玩家理解“顶层 effects”“隐式结果”。只在结构详情中展示这类信息。打开、查看、切换页签不能自动改写 JSON。

### 4.3 长文本、文案与空白

- 规则名是主信息，技术 ID 是次信息；两者独立分配区域。允许列表省略号，但必须能悬停或进入详情读取完整值。
- 关键错误必须完整可读：换行提示或问题面板，不能只有被截断的一行底栏消息。
- 摘要只保留“输入 → 产出 / 触发 / 每组消耗”，详细参数按需展开；不把所有 JSON 参数拼成一行。
- 用“每次消耗”“等待（秒）”“不限制条件”“结果 1”“轮流”“按顺序”“添加物品”等直观标签；算法和存储形态放说明。
- 必要留白用于阅读和分隔；剩余大块空间用于规则预览、效果参数或展开详情。只有一条的列表不要默认预留四条高度。
- 不删除现有用户 display_name、notes 或高级字段；所有新 HUD/GUI 文案使用本地化 key，同步中英文。

## 5. 三阶段任务与完成条件

### 第一阶段：功能与交互修复

依次实施小任务，每个可单独核验：

1. **F1 打开与原值保留**：统一规则打开路径，处理 effective/base/overlay 可查看内容与问题状态；修复备注长度与回填，查看不产生脏标记。
2. **F2 条件编辑接通**：调整能力注入顺序，接通规则级和效果级条件；提供鼠标添加/编辑入口。
3. **F3 切换和输入生命周期**：切候选/效果前提交有效编辑；处理无效输入、重建后的焦点、滚动、选择、冻结和只读状态；修正拖动行定位未使用列表滚动偏移的问题。
4. **F4 几何与命中**：补成本切换位置；按真实底栏高度保留区域；限制内容绘制/点击范围；接通子控件滚轮。先使所有关键操作可达。
5. **F5 展示事实一致**：统一 outcomes/effects 摘要、每组成本、名称解析与草稿搜索筛选；明确全草稿应用范围。

完成条件：已有规则、新建、复制、恢复规则都能查看并编辑；备注和未知字段不因浏览被改写；规则/效果条件可操作；切换不丢有效编辑；界面无跨区域命中；摘要与当前草稿和实际保存范围一致。

### 第二阶段：页面重排与视觉打磨

1. **L1 管理页**：接入类型树、选中预览、搜索/筛选/折叠状态与清晰的操作位置。
2. **L2 基本、输入、触发页**：内容按实际高度测量，目录选择和物品图标/名称可见，高级项按需展开，条件空态具有行动入口。
3. **L3 结果页**：按结果 → 效果 → 参数导航；单结果简化，复杂规则用并排详情或窄窗口分层。
4. **L4 全局文案与视觉**：统一间距、标题、状态、按钮和长文本策略；增加正确的“待应用 N 条”反馈和问题详情。

完成条件：管理页可快速定位规则；简单规则不被复杂结构术语淹没；复杂规则仍完整可编辑；长文本有完整阅读入口；小窗口也能完成全流程；空白分配随内容变化。

实现优先落在 common 的客户端业务层，按需要抽取规则展示/分类、页面布局和状态保持类；不把规则 JSON、目录协议或草稿概念塞进通用 kit。复用现有 UiTreeView、UiScrollView、UiFocusManager、主题和目录面板；确需修改 kit 时遵守 ADR-0025 并更新来源差异记录。无平台差异需要时不新增平台实现或 Mixin。

分类、标题和树数据在快照、草稿、搜索或语言变化时更新，避免逐帧遍历整套规则或发网络请求。裁剪前后使用同一布局数据，减少测量与事件坐标不一致。

### 第三阶段：游戏内验收与回归

由用户在 NeoForge、Fabric 上执行；不创建 test 文件。最低验收集：
