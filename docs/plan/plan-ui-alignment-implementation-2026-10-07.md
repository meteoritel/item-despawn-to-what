## 已确认的目标与边界

- 用户画像：懂 Minecraft、不了解规则 JSON 的整合包作者/服主。
- 页面范围：六张截图涉及的规则管理、四页编辑、放弃改动弹窗；目录、条件和效果选择入口按关联问题纳入。
- 保留 Minecraft 灰色像素风、自有 UI Kit。允许重排，最低 320×240 GUI 逻辑尺寸；窄屏采用单列、滚动或进入详情，不缩小字体硬塞内容。
- 规则管理采用虚拟分类树；实体产出下分掉落物、生物及其他实体、经验、组合产出；另有方块、战利品、世界事件、组合规则、扩展/未完成。每条规则只出现一次。
- 统一后端实体生成效果和子类；掉落物/经验专用入口；实体产物的邻近 limit/radius 移入服务端共用配置；方块放置的玩法半径/数量仍由规则表达。
- 阈值只检查转化组准入，已开始组不因邻近上限停止；经验按点，使用原版拆分和合并；不新增经验持久待发队列。
- 先静态审查与构建，完成本轮 UI 优化后由用户实测。不新增 test 文件，不以无法立即游戏测试阻塞问题登记与重排。

## 管理页草案：分类树与选中预览

Q16 已确认。宽屏：左侧树、右侧当前规则预览；窄屏：树占内容区，选中预览按需展开。

```text
规则管理        [搜索…] [状态筛选]       [新建] [模板]
┌ 分类树 ─────────────┬ 选中规则 ──────────────────┐
│ ▾ 实体产出         │ 鸡肉 → 腐肉    启用 · 草稿  │
│   ▾ 掉落物         │ 输入：鸡肉                  │
│     鸡肉腐化       │ 触发：自然等待 300 秒       │
│   ▸ 生物及其他实体 │ 产出：腐肉 1 件             │
│   ▸ 经验           │ 每组消耗：1 件源物品        │
│ ▸ 方块             │ [编辑] [启用/停用] [更多]   │
└────────────────────┴────────────────────────────┘
待应用：2 条规则  [查看改动]               [应用全部更改]
```

- 预览展示名称、输入、触发、产出、每组消耗及状态，不堆叠完整 JSON 参数。
- ID、来源与结构信息放详情，长内容可完整查看；符号必须有文字或 tooltip 解释。
- 新建/模板是全局操作；编辑/启用/复制属于选中规则；恢复、屏蔽、删除进入“更多”并说明作用范围。
- 保持稳定 ID 选择；搜索展开命中路径，清除搜索恢复折叠；分类变化不关闭正在编辑的规则。
- 窄屏的预览与操作必须能到达，固定底栏与正文命中范围分开。
- 当前保存仍应用所有 dirty 草稿；查看改动列出规则名称与变更类别，未应用草稿和服务端成功应用使用不同状态文案。

## 编辑流程草案：自由页签与完成提示

Q17 已确认。保留四个自由切换页签“基本 / 输入 / 触发 / 结果”；空白新建优先打开输入页，提供缺少输入/产出等可跳转提示，不强制顺序向导。

| 区域 | 默认展示 | 详情/高级 | 必须解决的问题 |
|---|---|---|---|
| 页头 | 可读规则名、启用状态、未应用标记 | 技术 ID、来源、版本 | ID 不挤占主标题，状态不是只有颜色 |
| 基本 | 名称、自动命名、启用 | 优先级、备注、技术信息 | 默认启用和优先级按有效值显示，查看不改 JSON；备注可完整查看/编辑 |
| 输入 | 源物品图标与名称、添加入口、每组消耗 | 排除项、标签、催化剂/消耗绑定说明 | 每个列表有明确目标的目录入口；手输若保留必须有格式与提交提示 |
| 触发 | 触发方式、自然触发等待、条件摘要与添加 | 组合、取反、条件参数 | 等待起点说清；只在真实出错时显示错误；空状态不铺全部高级按钮 |
| 结果 | 方案和动作的导航、添加入口、选中项参数 | 多方案选择策略、相关位置/安全设置 | 单方案隐藏无用策略；先必填产出，再相关高级项；取消规则邻近上限表单 |
| 底部 | 返回、撤销、重做、查看改动、应用全部更改 | 撤销动作名称在提示中展示 | 固定按钮长度；错误有完整详情，摘要不过度堆叠 |

- 既有规则保留自由编辑和撤销；新建缺少必填数据时引导到字段，不用绿色“已创建规则”暗示服务端已应用。
- 源物品、排除物品、催化剂的目录入口分别明确目标，选完回到对应列表。
- 统一实体效果选择子类后打开专用表单：掉落物编辑物品件数，实体编辑类型与个数，经验编辑点数与计算方式。
- 切换子类保留概率/延迟/条件，重置不适用专用参数并可一次撤销；查看不能自动转换子类或生成脏改动。
- 宽屏可采用导航与参数并排；窄屏优先选择方案/动作，再进入参数详情并提供返回，不把所有区域纵向压成大表单。
- 小窗口以实际可用宽高测量、裁剪与滚动；不能只靠截图像素宽度判定布局分支。

## UI 命名草案

Q18 已确认。用户可见层采用“结果方案 → 执行动作”。一个方案可以有多个动作，例如“生成掉落物、给予经验、改变天气”；多个方案之间按轮流或顺序选择。

| 现有 UI | 建议 UI | 领域对应 |
|---|---|---|
| 结果 1 / 添加结果 | 方案 1 / 添加方案 | 候选结果 Outcome Candidate |
| 添加效果 / 效果参数 | 添加动作 / 动作参数 | Effect |
| 轮询 / 按顺序优先 | 轮流选择 / 按顺序选择 | Combination Mode |
| 输入一个值 | 具体输入格式或添加物品入口 | 物品/标签匹配项 |

“动作”覆盖实体生成和世界变化，不把全部动作叫实体产物。源消耗仍主要放输入页；词汇表已记录 UI 别名，实现时同步两种语言，不改变“规则 → 候选结果 → 效果”的数据关系。

## 图标需求与能力边界

用户在 Q18 回复中明确要求加入物品/实体图标，让用途更容易一眼辨认；Q19 进一步明确实体直接使用旋转的 3D 模型，不采用上一轮 A/B 的刷怪蛋代表方案，也不将 3D 限于选中详情。

- 现有能力：UiIcon 支持原版 16×16 物品和 Sprite；ITEM/BLOCK 目录可解析物品栈，无物品形态的方块需回退。当前未实现实体图标、刷怪蛋映射或实体 3D 预览，仓库也没有自有图标贴图。
- 静态缺陷 B06：实体等目录无图标时，UiCatalogGrid 将名称裁剪宽度设为 1 GUI 像素，可能形成空槽；此回退必须修复，实际视觉效果优化后实测。
- 推荐放置：输入列表、产出动作列表、对象目录、选中规则预览；分类节点用类别图标。组合方案展示少量代表图标及“另有 N 项”，完整动作在预览中查看，不能用单个图标暗示全部候选必定同时执行。
- 图标补充名称、数量与状态，长名称提供 tooltip；不以图标或颜色替代文字。标签展示标签标识/范围，不以一件示例物品冒充唯一匹配对象；未知类型、无可视模型和渲染失败的边界须明确，不默默替换为刷怪蛋。
- 历史比较：此前建议代表图标或仅选中项 3D，以减小渲染成本；用户明确选择直接 3D，故按以下 Q19 契约执行。该比较保留为成本背景，不能用它降低已确认范围。
- 可复用目录映射缓存与 UiNode/UiDocument 图标能力；Q22 已确认通用实体绘制核心进 Kit，对象解析与缓存留客户端宿主层。缓存按对象类型/ID/预览相关参数，资源重载或切服失效；不在每帧创建物品栈或实体。
- 客户端当前根据目录类型和 ID 解析图标，并未读取协议条目的 icon 字段；客户端生成实体预览不要求修改服务端目录 DTO。

### 旋转实体 3D 图标（Q19 已确认）

- 物品和方块继续复用物品图标；通用实体条目在框中直接渲染自身 3D 模型，绕竖直中轴匀速旋转。目录、动作列表及规则预览复用同一组件，不能只在详情实现后声称完成图标需求。
- 根据框的实际可用宽高、模型尺度和旋转占用空间自适应等比缩放，居中并留边距；完整旋转期间保持稳定尺度，避免每帧缩放呼吸感。框裁剪防止渲染越界，不能把裁剪当作自适应缩放已成功的证据。
- 仅渲染可见项；在客户端缓存并限制预览对象数量，离屏项不绘制，不逐帧创建实体，不因目录全量缓存而全量创建预览对象。不添加实体到世界，不驱动玩法 tick。
- 渲染设施只在 client 层；按 Level 2 核对通用 Entity 渲染路径，不将只支持 LivingEntity 的原版物品栏函数误用于全部实体。绘制后恢复裁剪、矩阵、光照、阴影、朝向和相关缓冲状态。
- Level 2 已核对：通用 Entity 渲染可行；碰撞尺寸不等于可视模型包围盒，原版没有在已查入口提供统一的真实模型边界测量。Q21 已接受分层缩放与不可预览边界；不预先承诺任意模组实体的完整兼容或帧率。

### 原版 API 证据与特殊预览边界（Q21 已确认）

以下行号来自 IDEA 读取 vanilla merged jar 的反编译文本，路径以 `common/build/moddev/artifacts/vanilla-1.21.1-20240808.144430-minecraft-merged.jar!` 为根；未联网，也未采用 Level 3 替代查询。

- `EntityRenderDispatcher.class:99–106/137–147` 支持通用 Entity；`InventoryScreen.class:128–145` 的物品栏 helper 仅支持 LivingEntity，其局部 pose/满亮度/flush 流程可借鉴，不能直接覆盖所有对象。
- `EntityType.class:523–524` 的 create(Level) 返回 nullable，可构建客户端样例而不加入世界。仅存活当前预览缓存，不发 spawn packet 或运行玩法 tick。
- `Entity.class:424–425/3198–3203`、`EntityDimensions.class:24–27` 的宽高属于碰撞尺寸；`Entity.class:2848–2849` 默认 culling box 也不是真实可视模型范围。龙翼、长尾、外伸武器和模组模型可能超出估计。
- 适框推荐采用宽高与完整旋转占用空间估计作为初始值，并为原版明显偏离的模型补中心/尺度修正；具体效果在优化后实测。模组模型采用同一路径，但不能仅凭碰撞框保证任意自定义模型整圈完全无裁切。
- 用户指定：无可视模型、create 返回 null、缺 renderer 或绘制异常时，保留名称/ID，以屏障方块的物品图标兜底，统一显示“预览不可用”。图标使用客户端 ItemStack，不在世界放置屏障；提示使用本地化 key 并同步中英文。隔离失败，不因此禁止选择或修改规则。若对象需要内容数据才可显示，不用未标注的示例伪装规则实际产物；必要示例必须明确标为示例。
- `EntityRenderer.class:85/89` 的 getRenderOffset/render 可用于宿主直接渲染路径，避免修改 dispatcher shadow 状态；dispatcher shadow 无公开 getter，不能照抄原版 helper 的 setRenderShadow(true) 并称作恢复旧值。`EntityRenderDispatcher.class:385–386` 支持读取 cameraOrientation，需复制并 finally 恢复临时朝向。
- `GuiGraphics.class:133–136/167–172` 的 flush/scissor 与项目 `UiTransform.java:58–98` 可复用；在局部框退出前 flush，复用坐标变换后的 scissor，恢复 pose/朝向与 GUI 光照，避免污染后续物品或正文绘制。

Q21 最终结论：用户接受上述分层适框与模组模型实测边界，并明确屏障图标+“预览不可用”兜底。不追加任意模型的精确可视边界测量研究。

### 实体预览提取到 Kit API（Q22 已确认）

用户要求进一步探索是否有必要提取，并在 Q22 接受方案 B：提取通用实体绘制核心与可进入 UiIcon 的绘制适配；宿主继续承担对象创建、缓存、模型尺寸修正、目录和规则语义及项目指定兜底。

当前 UiIcon 是 sealed，只有 Item/Sprite，业务层不能直接实现；目录、管理树、方案/动作行、选中预览有四个真实接点，可复用相同绘制核心。Kit 已允许 Minecraft 客户端通用依赖，但脚本尚未放行必要的 com.mojang.blaze3d 渲染类。应按实际使用精确补白名单、公开 API 文档和 NOTICE，不以全限定名绕过约束。

完整证据、方案对比和已确认职责见 [Kit 实体预览提取方案](plan-kit-entity-preview-2026-10-07.md)。具体 Java 名称/签名由实施调用点确定，不能把文档职责示意当作当前已实现 API。

## 完整目录名称搜索与加载反馈（Q20 已确认）

用户接受按当前游戏语言的可见名称与资源 ID 搜索完整目录，不只筛选已显示的一页；没有翻译的对象继续显示和匹配 ID。加载中显示“正在加载”与仿 Windows 启动的环形点阵动画。

- 现有服务端用原始 ID/翻译 key 过滤，不知道客户端语言和资源包；此差异登记为 C01，未改服务端。
- 客户端可经现有协议按需串行拉取某一目录的所有页（每页最多 200 条），建立当前语言索引，再本地搜索/分页。现有同类型请求只保留最新 requestId，加载与搜索需统一调度，不能并发抢占。
- 尚未收齐时显示“正在加载”与环形点阵动画，另用简短说明区分搜索结果尚不完整；不能宣称“无匹配”。按需加载当前目录类别，不同时预加载全部目录。原始条目缓存不等于给每条构造图标或实体。
- 动画用若干点沿圆周追逐、速度/透明度变化表达等待，借鉴 Windows 启动的动感，不复制整屏启动界面。采用 UI Kit 的绘制和时间能力，不引入 GIF、播放线程或网络图片。
- 首次加载无条目时显示在内容区，分批加载已有条目时保持已加载内容并显示加载状态；全部完成后停止动画。加载失败/断线显示明确错误及重试入口，不用无限转圈掩盖失败；等待时不阻塞其他页面操作，也不伪造百分比。
- 切服/断线/会话结束清缓存，语言或资源包变化重建名称与图标；下次打开先核对目录 revision。跨页 revision 不一致时重拉并按 ID 去重。
- 已知限制：首次打开大目录需多次往返，10,000 条需至少 50 页，时延和服务端计算开销未实测；当前回包无总条数/页号，revision 是 ID 哈希而非严格元数据版本，也无主动目录失效推送。不能承诺巨型整合包立即得到完整结果或运行中变化立刻刷新。
- 已确认本轮采用上述客户端方案，保留服务端协议；巨型目录首屏即完整或即时重载同步不在本轮承诺内，若后续需要服务端目录快照/协议优化，先讨论责任和证据再实施。
