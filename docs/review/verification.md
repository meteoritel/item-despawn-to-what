# UI 三维审查独立核验报告（终版）

> 核验对象：[维度一·简洁性](01-conciseness.md)、[维度二·架构](02-architecture.md)、[维度三·风格](03-style.md)。
> 核验定位：审查结论 → 源码事实。所有条目回到源码逐条比对，不采信报告自身的计数结论。
> 状态口径：**核实**（定位存在且描述与代码一致）／**部分不实**（结论成立但存在具体数字或事实错误）／**无法核实**（需要运行时、原始度量脚本或产品判断）。
> 复核说明：本版为终态。三份报告按修订后现值全部复核，被核验条目无残留问题。

### 1.2 核验方式

1. **高优先级全量**：三维共 34 条高优先级条目逐条回源码，核对「相对路径 + 类名.成员名」是否存在、描述与实现是否一致、有无夸大。
2. **中低优先级抽样**：按报告自身编号抽样 45 条（维度一 15／维度二 11／维度三 19），覆盖三份文件；对每条实测其单位（方法体行数、参数个数、常量个数、引用文件数、字符串出现次数）。
3. **机械复算**：用脚本复核跨文件共有事实（包文件数与行数、protocol／gson 引用、主题静态调用、规则面板引用、失效文档指针）。
4. **格式与约定检查**：脚本解析三份文档的相对链接并逐个解析目标；解析 108 个条目的五要素；扫描行号式定位与过程叙述。
5. **修订复核**：对历次指出的需修订项逐条回到源码与文档核对现值；最终核验的 22 条清单与 03 H2、03 头部口径两处均已修订并通过。
6. **辅助工具**：运行 tools/check-docs.py（结果：66 个文档、608 条链接、0 违规，退出码 0）。该脚本只覆盖 Markdown，不作为 Java 注释指针的唯一证据。

### 1.3 计数口径

- **行数**统一采用**文本行数**：按文本行计数，末尾无换行的最后一行同样计为一行，文件末尾换行不额外产生空行。基线：kit 60／7577、theme 5／683、widget 23／11039、screen 20／8956、screen/form 18／6418、prototype 2／402、client 合计 173／40650、client/ui 128／35075。
- **引用计数**区分「import 条数」与「包／类型字符串出现次数」。
- 维度一 H2／H3 的相似度与同构段长度依赖原度量脚本口径，按无法独立复现处理。
