# 命令参考（/idtw）

输入 `/idtw` 查看当前身份可用的入口。正式命令按规则管理与编辑器分组；开发环境另外挂载 `/idtw debug`。

## 命令一览

| 命令 | 用途 | 权限 |
| --- | --- | --- |
| `/idtw` | 显示帮助 | 所有人 |
| `/idtw editor` | 取得独占编辑会话后打开 GUI | 有管理权限的游戏内玩家，客户端具备兼容编辑通道 |
| `/idtw editor status` | 查看编辑会话状态 | 所有人 |
| `/idtw editor release` | 强制释放编辑会话 | 权限等级 ≥2 |
| `/idtw rule list [页码] [筛选词]` | 分页查看已发布规则 | 管理权限 |
| `/idtw rule show <id>` | 查看已发布规则摘要 | 管理权限 |
| `/idtw rule show <id> raw [页码]` | 读取胜出来源的原始 JSON | 管理权限 |
| `/idtw rule enable <id>` | 设置本服启用 | 管理权限 |
| `/idtw rule disable <id>` | 设置本服停用 | 管理权限 |
| `/idtw rule reset <id>` | 删除本服设置，重新继承默认启用 | 管理权限 |
| `/idtw rule validate [页码]` | 重新读取来源并校验，分页查看问题 | 管理权限 |
| `/idtw rule reload` | 重载规则并排队回扫已有掉落物 | 管理权限 |
| `/idtw rule orphans [页码]` | 检查没有对应规则的本服启停记录 | 管理权限 |
| `/idtw rule orphans clear` | 清理孤儿启停记录 | 管理权限 |

## 权限与保存期间的行为

管理权限对单人存档房主直接放行；其他执行者要求权限等级 ≥2。开放局域网后的访客同样按权限等级判定。`editor release` 始终要求权限等级 ≥2，单人房主也遵守这一要求。

`rule` 分支按权限决定是否可用；无管理权限时执行 `editor` 会收到权限提示。控制台可以管理规则和编辑会话，打开 GUI 由游戏内玩家执行。

保存期间，规则列表、摘要和 ID 补全继续展示上一次发布的视图；文件校验、重载、原始来源读取、启停和孤儿检查提示等待保存结束。服务端运行时尚未就绪时会提示稍后重试。

## 查询列表与详情

`rule list` 按 ID 排序，每页显示 8 条，包含停用规则。首行给出筛选后的规则总数与启停数量；每行显示名称、ID 和生效启用状态，存在本服覆盖时附带“本服”标记。

```text
/idtw rule list
/idtw rule list 2
/idtw rule list 1 diamond
```

筛选词对 ID 与显示名做大小写不敏感的子串匹配，可包含空格。翻页保留筛选词，页码超出范围时提示总页数。悬停列表行查看来源与本服覆盖，点击行会把 `rule show` 命令填进输入框；翻页链接同样预填命令，按 Enter 执行。控制台会得到可直接输入的文本命令。

列表与普通 `show` 读取和运行时同步发布的视图：手动修改覆盖层文件后，执行 `rule reload` 才会更新它们。发布视图在启动、规则重载以及编辑器或命令成功应用修改时更新；重载失败保留上一份视图。

`rule show <id>` 显示发布来源、生效启用、默认启用、本服覆盖、优先级、消失方式、自然消失年龄门槛、结果方案数与行为数。行为统计包含结果方案中的效果。可识别 ID 但校验失败的条目会给出非法提示，并提供原始来源读取入口。

### 原始来源

`rule show <id> raw [页码]` 异步读取当前覆盖层文件与当前已加载的数据包基底，覆盖层优先，保留未知字段与声明值。它与普通 `show` 的已发布摘要分别标明来源口径；读取本身保持运行状态。

原始 JSON 会重新序列化，按有界片段分页，点击某一段可复制该段内容；依输出顺序拼接全部片段即可还原完整 JSON。分页时会重新读取来源。首次回显表示请求已受理，最终结果以随后反馈为准。刚加入覆盖层、尚未重载的规则也可按完整 ID 读取。

### ID 候选补全

在 `show`、`enable`、`disable`、`reset` 的 ID 位置按 Tab，可以选择已发布视图中的真实规则 ID。候选提示包含显示名、生效状态、本服覆盖与来源；补全只读取内存视图。

`show` 包含可识别 ID 的非法条目，启停候选只包含合法规则；`reset` 只提示有本服覆盖的合法规则。启用与停用命令保留所有合法候选，把继承状态改成同值的显式本服覆盖也是一次有效设置。

## 本服启停与恢复默认

`enable`、`disable`、`reset` 按存档保存设置，并使用已发布规则内容重建索引、排队回扫已有掉落物。命令反馈同时给出生效状态与本服覆盖。重复设置提示没有变化。

本服启停与规则文件的 `enabled` 分别表示本服覆盖和默认启用。`reset` 删除覆盖，重新跟随默认值；规则的默认值为停用时，恢复默认后也会停用。编辑器中的本服开关与恢复默认按钮提供相同能力，编辑器里的修改在保存时提交。

## 文件校验与重载

改完规则文件后，先执行 `/idtw rule validate`，再执行 `/idtw rule reload`。

校验会报告通过或发现错误，随后输出有效规则来源分布、错误与告警数量，再分页列出问题。问题包含来源与字段路径，错误显示为红色，告警显示为黄色。`rule validate 2` 查看下一页；每次执行都会重新检查来源。有错误时命令返回 0，校验通过返回 1。

重载先构建新规则，成功后才发布；已有掉落物的回扫随后在服务端预算内推进。部分文件或条目被拒载时，反馈明确说明已应用其余合法规则。读取或构建失败时，反馈说明保留原有规则与追踪。重载问题预览按页大小限制，更多问题通过 `validate` 查看。

`server.json` 在服务端启动时读取，修改后重启服务端生效，详见 [服务端配置](zh-07-server-config)。

## 孤儿记录

`rule orphans` 异步读取原始来源，再按 ID 判断哪些本服启停记录已无对应规则。规则内容校验失败但仍能识别 ID 时，该记录仍属于现存规则。来源读取、解析或 ID 识别出现错误时，检查与清理都会停止，并保留全部记录。

`rule orphans clear` 只删除孤儿记录。规则以后再次出现时，保留的旧记录会重新作用于它；清理后则跟随规则默认启用。两条命令首次回显表示请求已受理，最终结果以随后反馈为准。

## 编辑器会话

`editor` 在确认权限和客户端通道后取得独占会话，再发送 GUI 打开请求。当前已有持有者时，反馈给出玩家名与状态查询命令。

`editor status` 用“等待打开”“编辑中”“保存或回滚中”展示状态。持有者查看自身会话，有管理权限的其他执行者可查看持有者名；普通访客只看到已被占用。会话超时按服务端活动 tick 计算，游戏暂停期间保留剩余时间。

`editor release` 释放等待打开或编辑中的会话，并通知在线持有者会话失效；保存或回滚正在进行时，释放请求等到收尾后生效。
