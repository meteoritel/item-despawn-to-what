## 0. 使用说明

### 0.1 状态标记

| 标记 | 含义 |
|---|---|
| 【已有能力】 | 当前代码已具备，清单中作为前置条件或回归点，可直接执行 |
| 【待落地】 | 依赖本轮规格实施；代码合入后按步骤验收，合入前结果为「未实现」而非失败（2026-10-08：本轮已无条目使用，保留定义备用） |
| 【已落地，待游戏内执行】 | 代码已合入并通过双平台串行构建，但尚未在游戏内跑过；执行时按步骤判结果，失败口径同第 5 节 |
| 【落地后核对】 | 步骤可执行，但控件文案、字段标签或位置可能在实现中微调；执行前先按 1.6 节核对，别把文案差异当失败 |

### 0.2 判定口径

- 判定只看**玩家可观察**的内容：字段值、界面状态、按钮可用性、反馈文案、保存后的声明文件、游戏内转化结果；**不检查**控件私有字段、内部方法调用次数或代码结构。
- 一条场景内所有「期望观察结果」勾满才算**通过**；任一不符记**失败**，并按 5 节模板记录复现步骤与截图。
- 「保存后的声明文件」指覆盖层规则文件：`config/itemdespawntowhat/rules/<规则 id 把 : 与 / 换成 _>.json`。用任意文本编辑器只读打开即可，不需要理解其余字段。

### 0.3 本清单不覆盖的内容

独占编辑锁、心跳与租约、版本冲突、写盘失败、重载失败、旧配置迁移、数据包只读语义、快捷键绑定等仍是 [manual-acceptance.md](manual-acceptance.md) 的职责。本清单只覆盖本轮四页职责、文本输入、输入-触发联动与催化剂门槛/运行投影。

## 2. 验收样例规则（固定夹具）

为避免每条场景重复搭建，先建好下列样例；同一世界的同一批样例可贯穿 EA-02 至 EA-17。触发秒数一律改小（如 5 秒）以便观察。

### 样例 A：催化剂门槛（EA-06/07/08/10/11/13/15/16/17）

- 源：`minecraft:wheat_seeds`（小麦种子），排除项留空，触发方式「自然」。
- 输入页：勾选「添加催化剂」→ 选择 `minecraft:bone_meal`（骨粉）；配置独立消耗——催化剂消耗动作 `consume_catalyst` 数量 **C=2**、半径 2。
- 触发页：自动出现骨粉存在条件叶，最低数量 **T 留空**（期望显示「默认：2」）。
- 结果页：单方案，动作 `spawn_entity / item` = `minecraft:wheat`（小麦）×1。
- 用法：丢弃 **1 个小麦种子**，在落点附近放骨粉；等待约 5 秒观察。
- 保存后声明应形如：

```json
{
  "display_name": "催化剂门槛验收",
  "trigger_after_seconds": 5,
  "conditions": { "op": "all_of", "terms": [
    { "op": "leaf", "condition": { "type": "itemdespawntowhat:catalyst_present", "items": ["minecraft:bone_meal"] } }
  ] },
  "outcomes": [ { "effects": [
    { "type": "itemdespawntowhat:consume_catalyst", "items": ["minecraft:bone_meal"], "count": 2, "radius": 2 },
    { "type": "itemdespawntowhat:spawn_entity", "entity_type": "item", "item": "minecraft:wheat", "count": 1 }
  ] } ]
}
```

> 关键：`catalyst_present` 里**没有** `count`（T 留空），而 `consume_catalyst` 里**有** `count: 2`（每轮消耗 C=2）。两者是不同的变量，这是 EA-10/11/12 的核对核心。

### 样例 B：流体存在与独立移除（EA-14）

- **B1 存在 + 多组**：复制内置规则 `itemdespawntowhat:builtin_catalyst_and_fluid` 到覆盖层，把 `trigger_after_seconds` 改为 5；也可直接用样例 A 并勾选「添加流体」→ `minecraft:water`、`require_source` 关闭（流动水也算）。
- **B2 独立移除**：复制内置规则 `itemdespawntowhat:builtin_thunder_condensation`（含 `consume_fluid`），同样改小触发秒数。

### 样例 C：多同类叶 / 任一 / 取反 / 动作局部条件（EA-09）

- 规则级条件树：`all_of [ catalyst_present(骨粉), any_of [ catalyst_present(萤石粉 minecraft:glowstone_dust), inverted( weather clear ) ] ]`。
- 结果页：单方案内的一个动作额外带局部条件 `light_level 0..7`。
- 可用编辑器搭建，或先写覆盖层 JSON 再打开编辑器确认能逐项识别。

### 样例 D：纯存在条件、无消耗配置（EA-12）

- 只由输入页勾选「添加催化剂」→ 骨粉生成 `catalyst_present`；**不**配置任何催化剂消耗动作、**不**设置 `catalyst_cost`。

## 3. 逐场景验收

每条对应规格 Testing Decisions 验收场景表的一行（该表共 **18 行**：原文 132–151 行）。

### EA-01 空白新建与打开已有规则

- **对应**：场景「空白新建与打开已有规则」；规格 §页面与草稿契约。
- **覆盖**：两平台 × 两尺寸 × 两语言（按 1.4 矩阵）。
- **状态**：【已落地，待游戏内执行】
- **前置条件**：编辑器可用；管理页至少有一条已有规则（内置样本 `itemdespawntowhat:builtin_item_to_item` 即可）。
- **操作步骤**：
  1. 管理页点新建（选任意模板或空白）进入编辑器，记录默认页签。
  2. Esc 关闭并放弃草稿；在管理页打开已有规则 `builtin_item_to_item`，记录默认页签。
  3. 依次切换 基本 → 输入 → 触发 → 结果 → 基本；在输入页改一个可见字段（如排除项），切到触发页再切回。
- **期望观察结果**：空白新建默认停在**输入**页；已有规则默认停在**基本**页；四页可任意顺序切换，没有「下一步」强制顺序；切页后刚改的值仍在。
- **判定标准**：两次默认页正确 **且** 切页不丢值 = 通过。出现固定向导或必须按顺序 = 失败。

### EA-02 长名称与备注：首次从开头可读、备注真多行、仅浏览不产生脏改动

- **对应**：场景「打开完整长名称和备注、切页重开」；规格 §基本字段与输入控件。
- **覆盖**：两平台 × 两尺寸 × 两语言。
- **状态**：【已落地，待游戏内执行】
- **前置条件**：一条规则，`display_name` 为长文本（中文 40 字以上 + 英文短语，如「钻石雷鸣钻石雷鸣钻石雷鸣钻石雷鸣 / Diamond Thunder Diamond Thunder」）；`notes` 为 ≥5 行多行文本（含换行与空行，行尾放可辨识字符）。
- **操作步骤**：
  1. 打开该规则进入基本页，**不点击**输入框，直接读显示名框首个可见字符与末尾可见字符；悬停看完整内容。
  2. 观察备注框高度是否为 2–3 行以上、是否能换行；在备注内滚轮滚动，并用方向键把光标移到开头再移到末尾。
  3. 在备注内拖动选择一段跨行文本，Ctrl+C 复制到外部编辑器，比对换行与空行。
  4. 切到输入/触发/结果页再切回基本页；观察「应用」与撤销按钮的脏状态。
  5. 关闭界面（不应用）后重新打开该规则，重复第 1–2 步。
- **期望观察结果**：首次显示以**第一个字符开头**（不是尾部「er」「除。」之类）；备注是真多行控件（可见多行、可换行、可滚动），不是加高的单行框；仅浏览不产生脏改动（无脏标记、撤销栈为空、关闭不提示未应用草稿）；复制文本保留原换行与空行；切页重开后仍从开头显示。
- **判定标准**：①首字符可见且重开后仍从开头 ②备注可换行可滚动 ③浏览后无脏标记，三条全过 = 通过。任一不符 = 失败。

### EA-03 Unicode 码点长度上限（显示名 128 / 备注 1024）

- **对应**：场景「编辑中文及补充平面字符」；规格 §基本字段与输入控件。
- **覆盖**：至少「NeoForge × 正常 × 中文」与「Fabric × 较窄 × English」。
- **状态**：【已落地，待游戏内执行】
- **前置条件**：编辑器打开一条规则；准备外部文本编辑器以便粘贴补充平面字符（emoji）。
- **操作步骤**：
  1. 显示名输入 128 个中文（如「钻」×128）→ 再追加 1 个，观察是否被拒绝与提示内容（期望类「显示名超过 128 个字符」）。
  2. 显示名改为粘贴 64 个 emoji（如 🌱 U+1F331；一个 emoji 在 UTF-16 中占 2 个单元、即 1 个 Unicode 码点）→ 应为**恰好达上限**；再加第 65 个应被拒绝。若按 UTF-16 单元计算，64 个 emoji 就会被错误拒。
  3. 备注粘贴 512 个 emoji（=1024 码点）→ 应为上限；第 513 个被拒绝。
  4. 达到上限内保存，用文本编辑器核对声明文件中的 `display_name` / `notes` 未被截断、未乱码。
- **期望观察结果**：上限按 **Unicode 码点** 计；64 个 emoji 可保存、第 65 个被拒；512 个 emoji 备注可保存、第 513 个被拒；错误提示可读且指出字段。

- **覆盖**：两平台 × 两尺寸 × 两语言（含较窄尺寸下进入/返回方案层）。
- **状态**：【已落地，待游戏内执行】
- **前置条件**：样例 A（单方案）；另复制一条并添加第二个方案形成多方案规则。
- **操作步骤**：
  1. 打开样例 A 的结果页：**不点**任何「打开方案」类按钮，应直接看到动作与产出参数（数量、概率、延迟等）。
  2. 切到多方案规则：结果页出现方案选择层与选择策略（如轮流/按顺序）；尝试同时选中同组内两个方案。
  3. 在选中的方案内添加两个动作（如小麦 ×1 与经验 ×5），观察两个动作是否都保留。
  4. 在较窄尺寸（1.4 节）下进入方案层再返回；单方案规则在窄屏应直接从动作层开始，不出现方案层。
5. 观察结果页是否有说明行「消耗参数在输入页编辑」（仅在消耗类动作上出现）。
- **期望观察结果**：单方案（`candidates == 1`）**不建方案层**，宽屏左列直接是动作列表、窄屏阶段夹取在动作/详情之间；单方案不生成「打开方案」按钮；多方案才有选择层与「方案选取方式」策略；同组只能选一个方案；同一方案可含多个动作。
- **判定标准**：四项全过 = 通过。出现「同组同时选中两个方案」或多方案被隐去 = 失败。

### EA-16 输入消耗与结果动作高级项：消耗参数只在主入口编辑

- **对应**：场景「输入消耗与结果动作高级项」；规格 §输入定义与条件关联。
- **覆盖**：两平台 × 两尺寸 × 两语言。
- **状态**：【已落地，待游戏内执行】
- **前置条件**：样例 A。
- **操作步骤**：
  1. 结果页检查是否**没有**重复的「每轮消耗」主编辑字段（只允许查看/说明性展示）：消耗类动作（`consume_source` / `consume_catalyst` / `consume_fluid`）里应被隐藏的是 `consume_source→count`、`consume_catalyst→items/count/radius`、`consume_fluid→fluid`；`consume_fluid.require_source` **仍可**在结果页看到并编辑（输入页不管它），这不算失败。

### EA-18 窄窗口与两种语言：单位与入口可读、字段可达、长内容可滚动

## 7. 已知限制（写进清单，避免误判为失败）

以下四条是当前实现的有意取舍或平台控件边界，验收时按此口径判：

- **条件树叶行本身不显示编号**：编号（「类型 编号 · 作用域」）只出现在输入页存在条件标题行与叶弹窗标题上；触发页条件树的叶行没有编号不是缺陷。
- **输入页只列规则级存在叶**：动作局部存在叶只在触发页条件树里逐叶进入弹窗编辑；输入页看不到它们不是遗漏。
- **超大粘贴的极端截断**：显示名/备注一次性粘贴超过「2×码点上限」的纯补充平面字符（如 emoji）时，原版 `EditBox` 的 UTF-16 单元上限可能把文本静默截断到恰好上限而不弹超限提示；逐字符键入与常规粘贴不受影响。出现该现象记入现象栏即可，不判「超限无提示」失败；上限本身仍按 1.5 节与 6.3 的**码点**口径判。
- **流体类型改写不重指向「不同的」独立消耗配置**：只有当 `consume_fluid.fluid` 为空或与旧集合相同时才随类型改写（与催化剂同一规则，刻意不动用户另行配置的不同集合）。EA-08 的期望是「集合相同/为空的配置被同步」，不是全量覆盖。
- **撤销是按字段分条的**：`FormView.applyToDraft` 对每个真实变化的字段各记一条（`EditSession` 历史上限 100）。所以「勾选/取消存在条件」「逐项删叶」「类型改写 + 重指向」各是**一条**记录（可一次撤销整体还原）；而叶弹窗里同时改多个字段需要多次撤销，「弹窗确认」本身不是一条记录。
