# 规则编辑器四页职责与交互修正规格

日期：2026-10-07。状态：grill Q1–Q11 已确认；四页职责契约与统一人工验收入口已确认；2026-10-08 已按三个阶段实施完成（实施契约见 docs/dev/internals/editor-pages-contract.md，core 侧运行投影见 docs/dev/backend/systems/catalyst-threshold-projection.md；游戏内人工验收待执行）。本文是本轮实施与验收依据，讨论台账中的中间建议不构成额外要求。概念图已生成，作为布局参考。

## Problem Statement

玩家在规则编辑器中难以分辨「基本」「输入」「触发」「结果」的用途。界面重复展示摘要、技术路径和默认说明，重要入口却不直观：输入类型与触发条件分散，消耗参数跨页重复，单方案仍需先点击“打开方案”才能看到动作。

基本页将完整显示名“钻石雷鸣 / Diamond Thunder”和完整备注显示成尾部“er”“除。”。这源于输入框先在窄宽度下回填、将光标及水平滚动移至末尾，再布局时未恢复开头；原始数据没有被截短。恢复自动命名按钮的释放事件被前面的文本表单消费，可能无法执行并持续呈现按下状态；统一启用逻辑还覆盖了按钮自身的禁用条件。

玩家需要直接看懂每页能做什么，完整阅读并编辑字段，明确每轮消耗与触发门槛的区别，且无需了解 JSON 路径、运行模型或“隐式结果”等内部概念。

## Solution

四页共用同一草稿，可自由切换；空白新建进入输入页，已有规则进入基本页。通过短标签、具体控件和必要分组表达职责，不增加大段教学文字。

| 页面 | 玩家要完成的任务 | 常用操作与边界 |
| --- | --- | --- |
| 基本 | 识别和管理规则 | 顶部查看规则 ID；设置显示名或恢复自动命名；设置启用、优先级与备注。名称和备注不改变规则身份或转化内容。 |
| 输入 | 定义参与对象与每轮消耗 | 选择源物品或标签、排除项和源消耗；按需勾选添加催化剂、添加流体，再选择类型；配置独立的消耗设置。存在数量和环境判定在触发页配置。 |
| 触发 | 定义何时允许转化 | 选择触发途径与自然等待；自动呈现输入定义的催化剂、流体条件；设置最低数量、流体源要求和其他环境条件，按需组合全部、任一、取反。 |
| 结果 | 定义转化后执行的动作 | 单方案直接查看和编辑动作；多方案才显示方案选择与选择策略；配置产出参数，按需编辑动作概率、延迟及局部条件。消耗参数的主编辑入口在输入页。 |

基本页自上而下显示只读规则 ID、显示名与恢复按钮、启用、加高的优先级控件、默认 2–3 行的真正多行备注。删除基本页固定底部摘要、重复 ID、结构版本行及重复自动标题说明。页头保留当前实际生效名称；显示名为空时输入框以“自动命名”作占位。

催化剂每轮消耗量 C 与最低触发数量 T 独立。T 留空时有效门槛跟随对应 C；没有匹配消耗配置时默认 1 件。T 明确填写后保持独立，清空后恢复默认。触发页用“默认：N”表示留空时的有效值，不用说明段落重复解释。

流体继续按存在判定，不新增数量字段或份数预留；移除流体由独立消耗动作承担。界面调整保留既有条件组合和作用域，不把任一、取反或动作局部条件提升为全局必需条件。

## User Stories

1. 作为玩家，我希望四个页签各有清晰职责，以便直接找到要修改的内容。
2. 作为玩家，我希望自由切页而不用遵循向导，以便按自己的顺序配置规则。
3. 作为创建规则的玩家，我希望空白规则先进入输入页，以便从参与转化的物品开始。
4. 作为修改规则的玩家，我希望已有规则先进入基本页，以便确认正在编辑的对象。
5. 作为玩家，我希望仅靠短标签、分组和明确按钮理解页面，以便不用阅读大量说明。
6. 作为玩家，我希望基本页顶部显示稳定规则 ID，以便分辨名称相似的规则。
7. 作为玩家，我希望显示名首次打开时从开头显示，以便读到完整名称而非末尾几个字符。
8. 作为玩家，我希望显示名为空时看到“自动命名”，以便知道不填名称也能使用规则。
9. 作为玩家，我希望编辑名称不改变规则 ID，以便保持规则身份稳定。
10. 作为玩家，我希望备注支持换行、选择和滚动，以便阅读和编辑较长内容。
11. 作为玩家，我希望浏览或切页不截短已有名称和备注，以便保留原始内容。
12. 作为玩家，我希望文本框和优先级滑条更易操作，以便准确修改参数。
13. 作为玩家，我希望恢复自动命名按钮一次点击就生效并退出文本编辑，以便明确操作已完成。
14. 作为玩家，我希望恢复后输入框清空、标题更新、按钮禁用且有简短反馈，以便即使标题没有变化也能确认结果。
15. 作为玩家，我希望一次撤销可恢复原显示名，以便纠正误操作。
16. 作为玩家，我希望输入页集中编辑源物品、标签、排除项及每轮源消耗，以便清楚知道哪些物品参与转化。
17. 作为玩家，我希望只有勾选添加催化剂或添加流体后才展开类型字段，以便不被未使用的配置占据空间。
18. 作为玩家，我希望输入选择的催化剂和流体自动出现在触发页，以便不用重复选择类型。
19. 作为玩家，我希望修改类型后另一页同步显示，以便两页不会互相覆盖新值。
20. 作为玩家，我希望每轮催化剂消耗在输入页编辑，以便把付出与产出分开理解。
21. 作为玩家，我希望最低触发数量在触发页编辑，以便按需要设置独立准入门槛。
22. 作为玩家，我希望最低数量留空时跟随每轮消耗，以便常见规则不用填两遍数量。
23. 作为玩家，我希望明确填写门槛后不受消耗量变化影响，以便配置“存在多件、只消耗少量”的规则。
24. 作为玩家，我希望清空门槛后恢复默认跟随，以便能重新使用简单配置。
25. 作为玩家，我希望未启用催化剂消耗时默认只需 1 件，以便配置纯存在条件。
26. 作为玩家，我希望取消添加仅删除对应存在条件，以便保留独立配置的消耗行为。
27. 作为玩家，我希望在触发页删除条件时输入页取消对应添加状态，以便两页一致。
28. 作为玩家，我希望多个同类条件能逐项识别和编辑，以便不会误改或误删另一项。
29. 作为玩家，我希望任一、取反和动作局部条件保持原意，以便编辑类型不会改变规则逻辑。
30. 作为玩家，我希望流体只按是否存在判定且不显示数量，以便保留当前玩法特性。
31. 作为玩家，我希望流体存在要求与流体移除分别配置，以便可以浸润但不消耗流体。
32. 作为玩家，我希望正常选择触发途径后不再看到似乎报错的提示，以便识别真正的配置问题。
33. 作为玩家，我希望自然等待与动作延迟的含义和单位清楚，以便不会混淆两种时机。
34. 作为玩家，我希望单方案结果页直接展示已有动作，以便立刻查看和修改产出。
35. 作为玩家，我希望多方案才出现方案选择层，以便简单规则保持简单。
36. 作为玩家，我希望知道每组只选一个方案、方案内可执行多个动作，以便正确配置组合产出。
37. 作为玩家，我希望消耗参数只有一个主要编辑入口，以便不在输入与结果页重复修改。
38. 作为玩家，我希望动作概率、延迟和局部条件仍可按需编辑，以便保留高级行为。
39. 作为玩家，我希望只有缺少必要内容时才看到错误并能定位字段，以便正常页面不充斥无效信息。
40. 作为玩家，我希望小窗口仍能看清单位、入口并滚动到所需字段，以便不同 GUI 尺寸下都能使用。
41. 作为玩家，我希望切页仅保留草稿、应用才提交全部更改，以便清楚区分编辑状态与服务端生效状态。
42. 作为验收者，我希望保存重开、普通转化及 debug 入口使用同一门槛规则，以便配置与实际执行一致。

## Implementation Decisions

### 页面与草稿契约

- 四页使用既有编辑会话和共同草稿，不增加每页独立保存或固定步骤向导。切页继续检查未完成的无效编辑；应用提交整个变更集。
- 页面顺序是编辑分工，不能被解释成运行时先扣款再检查结果。继续保留候选筛选、条件求值、开组准入、结算与动作执行的既有分工。
- 使用领域词汇“输入要求”“结果方案”“执行动作”；界面可短称“方案”“动作”。不显示“隐式结果”和原始配置路径来解释普通操作。
- 用布局和控件表达职责；没有缺失项时不展示零缺失横幅；有效触发选择不恒显“至少选择一项”提示。仅基本页移除固定底部摘要，其他页按职责简化，不把概念图中的全部装饰性删减当成独立需求。

### 基本字段与输入控件

- 显示名绑定规则声明的 `display_name`，备注绑定 `notes`；数据来自当前编辑会话草稿。空白新建两者均缺失、输入为空；模板和复制保留原全文并另行生成身份。
- 显示名编辑后去除首尾空白，空值表示未设置；校验上限为 128 Unicode 码点，与规则校验一致。自动标题用于显示，不自动写入人工显示名。
- 备注编辑时保留换行及空白，真正空串删除字段；编辑上限为 1024 Unicode 码点。未编辑的既有原文保持完整，不在加载或浏览时截短。
- 程序回填从开头展示，用户输入期间保留正常光标和滚动行为；不在每帧布局时强制复位光标。单行与多行文本均按此约定处理。
- 多行备注使用实际多行编辑能力，支持换行、文本选择及长内容滚动；不以放大单行框或只提供 tooltip 代替。
- 修复公共文本输入的鼠标释放归属：只有真正承接对应按下或捕获的控件消费释放，按钮须收到其释放事件。复合表单遵循同一规则，不为恢复命名按钮写事件绕过特例。
- 恢复自动命名先提交有效编辑缓冲，再删除显示名，刷新控件与当前标题，退出旧文本焦点，显示简短成功反馈。保持按钮自身可操作条件，恢复后禁用；即使人工名等于自动标题也能确认操作，一次撤销可还原。

### 输入定义与条件关联

- 输入页定义源匹配、催化剂物品类型、流体类型及独立消耗；触发页定义存在判定和条件组合。添加选项未选时不渲染对应类型编辑字段。
- 既有条件表达式中的具体条件叶是类型的单一事实源，不新增顶层类型副本。输入与触发按确切条件叶路径关联，重建和切页不得让旧表单缓冲覆盖新类型。
- 新增简单存在要求作用于整条规则：空条件树直接新增叶；已有根不是全部组合时，将完整旧根与新叶置于新的全部组合中，不根据当前选中的任一节点擅自插入。
- 已有多同类条件逐项关联，提供必要的简短编号及作用域识别；不只绑定第一项、不按类型全删、不改变任一或取反结构，不将动作局部条件提升到规则级。
- 取消输入添加删除对应存在叶与类型；触发删除同一叶同步清除输入项。整理空父组，相关修改构成一次可撤销操作；独立消耗动作和固定成本仍由自己的开关或编辑入口控制。
- 输入页是消耗参数主入口，结果页避免重复提供相同字段。保留既有消耗动作所在方案及其概率、延迟、局部条件；不得因主入口调整而生成重复固定成本。
- 固定源成本与源消耗动作互斥，固定催化剂成本与催化剂消耗动作互斥；继续既有跨规则方案的同类消耗声明限制。非法草稿给出校验，不能默认为覆盖优先级。
- 源消耗动作的数量继续决定全规则开组源成本；固定催化剂成本是开组支付要求，催化剂消耗动作属于具体方案且可能部分扣除或跳过。界面不把两者暗示成同一种全局足额支付。

### 催化剂门槛与运行投影

- 条件声明保留最低数量未填写的状态；显式门槛继续校验 1–64。新催化剂叶不预写门槛 1，也不根据“数值恰好等于消耗量”猜测自动模式。
- 消耗量 C 与门槛 T 是不同变量。T 缺失时，按对应对象与条件作用域解析消耗量；没有匹配消耗配置时使用 1。T 显式存在时使用 T，修改 C 不覆盖 T，修改 T 不反向改 C。
- 例：C=2、T 留空，有效门槛 2；C 改为 4，T 仍缺失、有效门槛 4。明确 T=6 后修改 C，门槛仍为 6；清空 T 后重新跟随当前 C。
- 采用已接受的 ADR-0027：编辑和序列化保存声明，运行入口生成带具体有效门槛的条件投影。派生值不反写保存数据，不扩展公开条件求值上下文承担规则配置查询。
- 共用投影解析入口覆盖普通规则索引、debug 绕过索引入口以及规则级和动作局部条件。按照既有规则与配置生命周期构建或刷新，避免每次条件求值重复复制整树，不另建第二套规则索引。
- 对应关系按具体叶、对象引用与成本或动作确定；不能用任意第一条同类消耗覆盖不同对象或不相关作用域。

### 流体、触发与结果

- 流体存在检查保持当前位置、类型及是否要求流体源方块的既有行为；不增加数量、扫描范围、份数预算或按流体消耗量限制组数。
- 流体移除保留独立动作：含水方块关闭含水状态，其余按现有执行器移除匹配流体；无可移除流体时按现有规则跳过。不把存在检查当成已执行移除。
- 存在检查与移除动作的类型匹配语义沿用各自现状，不默默统一同族流动变体与精确 ID 匹配；不顺手更改新建流体叶与字段省略时的既有源方块默认行为。
- 自然等待表达掉落物年龄门槛，环境销毁途径在对应事件发生时检查；动作延迟留在结果页，关键单位完整可见。
- 一个方案直接展示其动作和产出参数，不经过“打开方案”。多个方案保留方案选择层和既有轮流或按顺序选择策略；每组选择一个方案，同方案可有多个动作。
- 动作概率、延迟及局部条件保留高级编辑入口；常见物品、实体和经验产出使用具体字段，不以内部实现说明代替操作入口。
- GUI 文本统一本地化，同步中文与英文；保持现有平台隔离、端隔离及 UI kit 依赖边界。

## Testing Decisions

- 用户已确认沿用现有规则编辑器 → 应用规则 → 游戏内转化作为主要验收入口，必要时使用现有 debug 入口；最后统一人工实测。不新增 test 文件，不搭建新的测试框架或专用测试接口。
- 好的验收检查玩家可观察的字段、交互、保存声明与转化结果，不检查控件私有字段、内部方法次数或代码结构是否与某个实现相同。
- 范围包括编辑会话与撤销、文本输入和释放路由、输入与条件树关联、声明序列化、运行条件投影及实际转化。使用已有编辑、应用、debug 与人工验收机制，避免新增多个重复入口。
- 每个实施阶段先经 IDEA MCP 检查工作区错误和警告，修复本轮引入的问题后再通过项目串行构建包装脚本构建；上一轮未结束不得重复启动。文档单独修改无需构建或 Markdown 格式校验。
- 统一人工验收覆盖 NeoForge 与 Fabric、正常和较窄 GUI 尺寸；执行时提供独立玩家验收清单，存放在用户指南目录。

| 输入勾选/取消催化剂和流体 | 类型框按需出现；触发同步对应叶；取消仅删关联存在条件，独立消耗保留。 |
| 触发删除存在叶 | 输入同步取消对应项，一次撤销恢复关联；其他同类叶不受影响。 |
| 修改类型后切页、保存重开 | 两页始终读取相同类型，旧缓冲不覆盖新值。 |
| 多同类叶、任一、取反、动作局部条件 | 逐项编辑不误绑，不改变组合及作用域，保存后逻辑一致。 |
| C=2、T 缺失；修改 C=4 | 有效门槛分别为 2、4；保存声明持续不含显式门槛。 |
| 显式 T=6 后修改 C；随后清空 T | 前者仍用 6，后者跟随当前 C；C 不因编辑 T 改变。 |
| 仅存在条件，无匹配消耗配置 | 门槛未填时默认 1；对应对象不足与足量时实际条件分别不通过、通过。 |
| 普通运行、保存重载与 debug 执行 | 同一声明产生同一有效门槛；配置更新后不继续使用旧投影。 |
| 流体存在、独立移除及多组转化 | 沿用既有存在判定和移除副作用，不新增按量准入或份数预留。 |
| 单方案与多个方案 | 单方案直达动作；多方案有清晰选择层，同组只选一方案。 |
| 输入消耗与结果动作高级项 | 消耗参数只在主入口编辑；既有作用域、概率、延迟和条件保留。 |
| 正常配置与缺失必要项 | 正常页无零缺失横幅及伪错误；真实缺失可定位。 |
| 窄窗口和两种语言 | 单位及主要入口可读，字段可达，长内容可滚动，无技术路径挤占常用区。 |
