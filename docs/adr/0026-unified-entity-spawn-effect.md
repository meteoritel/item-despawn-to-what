# ADR-0026：统一实体生成效果，按产出子类分发

> 状态：已实施；实现见 `core/type/effect/SpawnEntityEffect.java` 与 [类型系统](../modules/type-system.md)。

掉落物生成、通用实体生成与经验生成合并为一种实体生成效果，按产出子类分发：`SpawnEntityEffect` 持有 sealed `EntityProduct`，由 `variant` 分派 item / entity / experience。通用实体子类覆盖生物与其他实体；掉落物与经验球固定走专用子类，通用实体子类拒绝 `minecraft:item` 与 `minecraft:experience_orb`。数量按物品件数、实体个数、经验点数计量；经验点数按每件源物品的定义值乘以本组实际扣减的源物品件数计算，各子类的数量直接取自自身参数。JSON 使用扁平字段，见[类型系统](../modules/type-system.md)。

考虑过保留三类独立后端效果、只统一界面分类的方案。最终选择把统一抽象落实到后端，使规则类型、校验与编辑入口围绕共同概念组织；具体产物的参数通过子类表达。各子类保留自身计量单位，不因公共实体基类而混同。

经验按每个转化组内的单个经验行为汇总点数：每件源物品的点数乘以本组实际扣减的源物品件数，只计算一次，随后采用安全单球容量装载与分批调度，以减少实体数量和瞬时生成开销，不截断经验总量。单球容量同时遵守原版存档和网络字段的数值边界，保留原版拾取与后续同值合并；生成位置采用面积均匀的水平极坐标圆盘，避免方形散点。不同组及不同经验行为的概率、条件与延迟不合并。经验球存量不参与转化组准入，避免经验容量不足导致源物品返还；物品/通用实体的邻近 limit/radius 仍由服务端配置统一提供，所有规则共用，生成数量仍由规则表达。

物品和通用实体采用完整组准入：只有相应容量足够才启动完整转化组，受阻组不支付成本，保留或返还源物品；含经验的混合产出仍须通过这些检查。组一旦开始执行，就不再因邻近上限暂停、截断或取消产出，允许已开始组完成后超过阈值；新组继续受物品和通用实体准入检查约束。此阈值不是硬存量上限。经验产出由执行状态的剩余点数跨步骤续接；容量不足时按已开组数截断组数，剩余源库存走返还路径。分批预算、区块检查、概率、条件与中断机制分别按既有契约处理。仅保证不因该邻近阈值中断，不能据此承诺所有效果事务性成功。

超过阈值的产物由拾取、消失等世界变化回落；调度器不按阈值删除已生成产物，回落所需时间不固定。

规则管理采用虚拟分类树：实体产出下分掉落物、通用实体、经验与实体组合产出，跨根类别的规则归组合分类；其余一级分类含方块、战利品、世界事件与扩展。每条规则只归一个分类。

`Effect` 与第三方效果注册机制仍是事实基础：子类使用 Codec 扁平分派及专用执行策略，不改变规则 packet 的 JSON 载体；子类集合封闭，新增内置子类须同步 Codec、执行器与 UI，第三方可继续注册独立 EffectType。统一实体生成只覆盖直接产出实体的效果，方块、战利品与世界事件类效果保持各自类型。
