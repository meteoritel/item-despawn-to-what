# 统一实体生成效果，按产出子类分发

用户于 2026-10-06 开始确认本决策，并于 2026-10-07 明确执行途中的上限边界：将目前独立的掉落物生成、通用实体生成和经验生成合并为一种实体生成效果，按产出子类分发。当前仍处于开发阶段，新契约直接替换旧格式，随实现重写项目内现有示例/测试 JSON，不要求数据迁移。通用实体子类支持生物之外的其他实体。掉落物和经验球固定通过专用子类配置，通用实体子类不接受 minecraft:item / minecraft:experience_orb。数量按物品件数、实体个数、经验点数计量，保留按实际消耗源物品数计算经验的选项。此决策已实施：`SpawnEntityEffect` 持有 sealed `EntityProduct`，由 `variant` 分派 item/entity/experience。JSON 使用扁平字段，见 [实体产物指南](../guide/entity-products.md)。

考虑过保留现有三个后端效果、只统一 UI 分类的方案。最终选择将统一抽象落实到后端，使规则类型、校验与编辑入口围绕共同概念组织；具体产物的参数通过子类表达。各子类保留自身计量单位，不因共有实体基类而混同。

经验点数按原版经验球拆分算法分配，保留原版合并逻辑；附近经验球存量作为启动转化组的准入阈值。阈值由服务端配置统一提供，所有规则共用，不由规则 JSON 单独指定；现有配置入口为 `config/itemdespawntowhat/server.json`。用户已确认原有物品/通用实体的邻近 limit/radius 一并移入服务端配置，生成数量仍由规则表达。默认值由实施方案给出。

用户选择容量不足方案 A：只有容量足够才启动完整转化组，受阻组不支付成本，保留或返还源物品。组一旦开始执行，就不再因邻近上限暂停、截断或取消产出，允许已开始组完成后超过阈值；新组继续受准入检查约束。此阈值不是硬存量上限。不引入经验持久待发队列，也不引入因上限受阻而等待的分支；已有分批预算、区块检查、概率/条件和中断机制分别按原契约处理。仅保证不因该邻近阈值中断，不能据此承诺所有效果事务性成功。

超额回落依赖拾取、消失或其他世界变化；当前未要求定时清理产物，不保证固定时间内回到阈值。已生成产物不因为超过阈值而被删减。

规则管理采用虚拟分类树，实体产出下分掉落物、生物及其他实体、经验和组合产出；跨实体与方块/世界事件等的规则归一级组合规则。其余一级分类含方块、战利品、世界事件、扩展/未完成，每条规则只出现一次。

当前 `Effect` 和第三方效果注册机制仍是事实基础。子类使用 Codec 扁平分派及专用执行策略，不改变规则 packet 的 JSON 载体；子类集合当前封闭，新增内置子类须同步 Codec、执行器与 UI，第三方可继续注册独立 EffectType。也不把统一实体生成扩大为合并所有会创建实体的世界事件。

本决策允许开展上述后端结构改造。排查中偶然发现的服务端 Bug 仍按用户要求先保存证据并讨论，不视作同一授权。

用户已确认后续按三个顺序任务拆分：模型/分发/校验 → 执行/结算/资源 JSON → UI 分类/子类编辑。用户已确认开始实施，三个任务均已落盘；游戏验收由用户执行。
