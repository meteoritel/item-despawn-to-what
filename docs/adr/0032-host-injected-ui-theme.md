# ADR-0032：UI 主题与样式由宿主注入

- 状态：已接受；kit 依赖边界见 [UI kit 文档](../dev/internals/ui-kit/README.md)。
- 依据：主题静态取色的实测结论，以及用户对「主题是否改为宿主注入」的答复。

## 背景

[客户端层文档](../dev/layers/client.md) §4.2 写主题「把调色板映射成 kit 所需的样式对象后注入」，实际是业务控件静态取色；画布页与表单页各持一套主题，配色变化要跨多处修改。kit 的目标是可独立发布的库 API（见 [ADR-0029](0029-client-dependency-boundary-and-shared-subpackage.md)、[ADR-0030](0030-ui-kit-as-standalone-library-api.md)），不能硬编码本模组的主题与调色板。

## 决策

1. **kit 只提供接口**：kit 定义样式与主题接口，不实现本模组视觉规范。
2. **宿主注入主题**：宿主侧主题实现接口并经注入传给控件与消费点，业务控件不再静态取色。
3. **宿主入口默认提供现行主题**：主题由宿主入口装配，既有画面不变。

## 考虑过的替代方案

- **保留静态主题访问**：kit 依赖全局状态，无法独立发布，也无法在测试中替换主题。
- **让 kit 自带主题**：宿主视觉规范渗入通用库，换主题要改 kit。
- **一次性全量迁移所有控件**：涉及控件层与界面层共 30 余文件，单次迁移风险不可控。

## 后果

- 控件取色经注入接口，主题与视觉规范归宿主侧。
- kit 不依赖本模组主题实现，具备独立发布的边界条件。
- 主题替换与界面测试不再依赖全局静态状态。
