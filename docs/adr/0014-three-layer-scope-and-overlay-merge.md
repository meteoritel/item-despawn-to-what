# ADR-0014：三层配置作用域与按 id 覆盖合并

- 状态：已实施；实现见 `core/load/RuleLoader.java`、`core/load/RuleMerger.java`、`core/load/RuleSourceIndex.java`。

## 背景
旧链路把配置放在 `config/itemdespawntowhat/<ns>/<type>.json`：既是唯一来源，又是 GUI 的写入目标；"数据包只能改配置目录"导致整合包作者无法用数据包分发默认规则，而 GUI 一保存又整文件覆盖，把 disabled / 编译失败 / 未命中标签的规则直接删掉（A1）。

## 决策
1. **三层作用域**，优先级 **config 覆盖层 > 世界数据包 > 内置数据包**：
   - ① 内置数据包 `data/<ns>/idtw/rules/**`（mod jar 内，只读，作默认与示例）；
   - ② 世界数据包 `datapacks/*/data/<ns>/idtw/rules/**`（只读，原版机制同步）；
   - ③ config 覆盖层 `config/itemdespawntowhat/rules/**`（**唯一可写**，GUI 保存目标）。
2. **文件形状**：单条规则对象或规则数组；`id` 优先取字段，文件只含单条规则时可省略并由文件路径推导（数据包 `<ns>:<路径去 idtw/rules 前缀与扩展名>`，覆盖层 `<规则命名空间 idtw>:<相对路径>`）。
3. **按 id 逐条合并**：不同 id 叠加，同 id 后者胜；合并结果保留每条规则**最终生效的来源标识**。
4. **覆盖层条目承载完整规则内容**：同 id 覆盖条目整条替换基底内容；撤销一次覆盖就是删除该条目，基底原样恢复。本服启停状态不写规则文件，按存档保存（见 [ADR-0044](0044-rule-enable-state-layering.md)）。
5. **逐包取副本**：数据包层用 `ResourceManager.getResourceStack` 取回同名文件在**所有包**中的副本，避免高优先级包遮蔽低优先级包里的其它规则。
6. **严格拒载**：文件解析失败整文件拒载；单条非法只拒该条；错误带来源与字段路径。

## 考虑过的替代方案
- **单一 config 目录（旧做法）**：简单，但数据包不能分发规则，也无法把"只读基底 + 可写覆盖"分层。否决。
- **覆盖层整文件替换**：实现简单，但会删掉未出现在 GUI 视图里的规则（A1 的根因）。否决。
- **按文件覆盖（后加载的文件整体替换同名文件）**：粒度太粗，一个文件里的多条规则无法逐条控制。否决。

## 后果
- 整合包作者可以用数据包分发规则，玩家用 GUI 覆盖而不破坏基底。
- `/idtw config list` 标注每条规则的来源层与生效状态（id / layer / priority / trigger_seconds / effects / enabled / origin）。
- 加载顺序必须显式排序（层优先级 → 包优先级 → 文件路径 → 文件内顺序），不能依赖遍历顺序。
- "内置包"与"世界包"的判定按本次已加载包的来源元数据（KnownPack 命名空间）构建快照，由引导层经 `PackLayerResolver` 注入。来源元数据只作工程分类，不承诺防伪造。
