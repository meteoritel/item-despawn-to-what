# ADR-0043：消失方式触发、结果预算与实际源消耗结算

- 状态：已实施。
- 实现见：`core/model/TriggerKind`、`CombinationMode`、`SourceCost`、`CatalystCost`、`OutcomeCandidate`、`Rule`；`core/runtime/ConversionSettlement`、`CatalystReservations`、`SettlementLedger`、`SettlementRecord`、`SettlementRecovery`、`RoundRobinCursors`；`core/state/DropState`。
- 规则模型关系见 [ADR-0012](0012-rule-model-and-effect-list.md)；预算术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## 背景

源物品提供的结果预算与环境允许的执行数量是两份独立额度。方块要等延迟任务实际遍历位置后才能确定成功量，开组即扣完整源成本会让半径或数量上限截断的余量失去返还依据；同时恢复需要清楚知道已经消费与仍持有的源库存。

## 决策

1. **消失方式集合 `triggers`**：`natural`（默认，未声明时）/ `fire` / `lava` / `cactus`。火 / 岩浆 / 仙人掌由两端**最小 Mixin** 接 `ItemEntity` 致死分支（原版物品销毁回调之前）接管，**即时触发、不等待**；按**最终致死伤害**归因（岩浆优先于火，未知伤害不归为火）；只有原版物品销毁分支（`onDestroyed` 之前）会被接管。Mixin 只做入口，规则匹配与结算仍在 common。
2. **输入准入与支付**：源成本为正整数，催化剂门槛与实际消耗分开声明，流体按规则开关追溯源方块支付。数量与共享半径契约见 [ADR-0041](0041-input-thresholds-and-consumption.md)；输入配置不声明独立概率或延迟，方块源占用随实际执行进度发生。
3. **准入组与两类预算**：源数量除以固定源成本向下取整，确定可准入组数；不足一组时不开组。物品、通用实体与战利品按初始邻近存量和声明产量取得环境预算，组间只递减、不重查、不因少产补组。方块结果预算由准入组的 count 给出，环境预算由执行时的半径位置与 limit 限制；同目标组共享一次扫描，保持逐组随机结果与到期刻。
4. **候选结果 `outcomes` + 组合模式 `combination`**：一轮一组只选**一个**候选；`round_robin`（默认，按游标依次选取）或 `priority`（取第一个可执行完整一组的候选）。轮询游标按**规则 id + 维度**共享并持久化，不随换源清空。未声明 `outcomes` 时，顶层 `effects` 由 `Rule.effectiveOutcomes()` 隐式映射为唯一候选 `default`（兼容旧格式）。`effects` 与 `outcomes` 不得同时声明。
5. **一次性世界效果**（lightning / explosion / weather）不参与容量计算；仅含一次性效果的候选对同一源最多尝试一组。可重复的世界效果按候选与槽位合并为一次延迟任务，逐组保留到期刻与固定输入，见 [ADR-0058](0058-arrow-rain-series-batch.md)。
6. **实际源消费与守恒**：原始源量 = 实际消费 + 已交付返还 + 待交付返还。有效方块槽位按 ceil(成功量 × 每组源成本 / count) 占用该组源成本，多槽取最高占用；其他实际派发行为、概率落空与无效固定输入占用完整组成本。催化剂与流体沿用开组支付。按组向上取整避免支付半件源物品，同组成本上限避免混合效果重复收费。
7. **延迟终态与持久返还**：结算等待全部子效果终态，再返还未消耗源库存并完成账目。中断时先取消子任务，再记录剩余库存，由恢复任务在目标维度可用时交付；已开始效果不重放，已写入世界的结果保留。每次实际源消费与待返还减少在同一账目提交中完成。
8. **产物与返还物状态**（`core/state/DropState`）：新产物默认 **2 秒**保护（仅防火 / 岩浆 / 仙人掌）与 **5 秒**转化冷却；未消耗源返还物在本实体生命周期内**永久**防上述三类伤害且**永久禁转**。状态存**实体层**（不随 `ItemStack` 进背包），服务端 tick 计时、重启保留；拾取后重丢是普通掉落物，不继承永久状态；状态不兼容的掉落物禁止合并。
9. **位置策略**：候选级 `safe_spawn`（生物安全生成，水平 5×5、上下各 2 格；找不到安全位置时本次转化失败，本组源成本退回）与 `fill_origin`（方块起点填充，默认开启）开关；返还位置搜索受公共调度预算分步约束，必要时在限高以上生成。

## 考虑过的替代方案

- **回滚已执行的世界效果 / 恢复未完成组**：需要为每个世界操作做补偿，原版 API 不提供，复杂度与风险都过高。否决。
- **保留 0 源成本**：会让「不消耗输入」和「消耗但概率跳过后免费重试」都变得可表达，账目无法守恒。否决（不希望消耗的输入应作为催化剂）。
- **把流体按数量换算可执行组数**：会把「存在条件」和「数量成本」两类语义混在一起，且需要扫描流体总量。否决（流体按存在条件与规则级消耗开关控制）。
- **开组先扣完整源成本、结束再反向退款**：会在中断恢复中同时维护扣款与补偿两份状态。采用未消费源始终留在结算库存的方式，恢复沿用单一守恒式。
- **每组独立重扫候选位置**：环境受限时工作量随组数重复增长。按同候选、槽位与目标合并扫描，仍逐组报告消费。

## 后果

- 源成本同时承担准入门槛和每组消费上限；源消费不再由已开组数直接推算。规则 JSON 字段与版本保持现行契约。
- GUI 表达触发、固定成本、候选与组合模式；无法表达新结构时**拒绝可能丢字段的保存**（见 [编辑协议](../api/edit-protocol.md)）。
- 源物品整数舍入、混合效果占用与催化剂／流体开组支付可分别核对；正常结束与中断共用未消费库存返还。
