# ADR-0051：结算库存单一来源与生命周期所有权

- 状态：已实施；实现见 [conversion-runtime](../modules/conversion-runtime.md)。
- 相关决策：[ADR-0043](0043-result-budget-and-source-settlement.md)（实际源消耗与返还语义）、[ADR-0034](0034-scheduler-contract-and-implementation-layering.md)（调度契约分层）。

## 背景

转化扣减源堆后，消费、退款与返还交付会跨多个调度步骤发生，取消和恢复也要读取剩余数量。若任务另持一份可变源堆，再在步骤出口覆盖账目，库存一致性就依赖两份状态的同步顺序。回执接收资格、子任务取消与库存移交还需要统一的生命周期所有者。

## 决策

1. **账目是剩余库存的唯一来源**：消费、退款和成功返还经受控 Writer 等额更新守恒项；源物品快照只承载物品类型、组件与触发信息。完成的前提是待交付量已为零。
2. **聚合根协调终结**：执行阶段表示结算任务是否仍持有交付权。中止先进入终态，关闭效果、进度与退款接收，再取消子任务、释放预留并记录持久结果。执行阶段与持久结果分别表达推进位置和可恢复业务结果。
3. **保留受控写入句柄**：账目私有变更与双索引维护、标脏由 Writer 配套完成；步内变更合并提交，步外回执立即提交。提交遵循 SavedData 的保存粒度。
4. **共享有界交付循环**：活跃结算与恢复均从同一账目分堆、续接选址并确认已交付数量；调用方按各自任务生命周期处理完成与重试。恢复任务与恢复队列共用恢复退避计算。
5. **初始产出预算固定**：计划期覆盖全部候选，按理论产量查询邻近存量并分配开组预算。跨刻续接保留已完成项；生成期间递减本地预算，外部新增产物不挤占已分配额度，实际少产不补开组。

## 考虑过的替代方案

- **保留可变源堆并集中覆盖账目**：消费和退款仍需双写，统一出口无法消除数量来源重复。
- **只抽取返还循环，分别适配两种数量来源**：交付代码得到复用，但库存同步的根因仍在。
- **把执行阶段与持久状态合为一个枚举**：执行准备阶段与持久业务结果并非一一对应，恢复也不重走执行阶段。
- **删除 Writer，由调用方直接更新字段与提交**：索引和标脏重新分散，遗漏提交的路径随业务出口增加。
- **引入通用事务或重试策略框架**：当前差异由局部库存约束、任务终态与明确的停止原因即可表达，通用框架扩大了调用方需要理解的机制。

## 后果

库存变化集中在语义写入入口，新增消费、退款和交付路径均使用同一守恒口径。迟到回执由聚合根终态统一拦截。活跃执行与恢复共享世界交付机制，同时保留各自的重试节奏与结束责任。正常保存后的恢复遵循账目剩余量；世界写入与自动保存保持现有存储粒度。

初始预算在结算内固定，外部新增产物后最终存量可以超过邻近阈值。
