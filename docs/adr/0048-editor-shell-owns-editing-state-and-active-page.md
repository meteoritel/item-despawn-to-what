# ADR-0048：编辑器共享状态与跨页命令收进编辑器外壳

- 状态：已实施。
- 依据：编辑器页三层转发链与双真相的实测（五个宿主适配接口、约 223 行逐方法委托、40 处模式分支、27 处空页守卫），以及用户对形态与页面归属的选择。
- 相关决策：[ADR-0029](0029-client-dependency-boundary-and-shared-subpackage.md)（客户端依赖边界；本 ADR 只在屏幕内部重组页接口，不新增跨层依赖）。

## 背景

规则编辑器的三个页（管理页、编辑页、调试页）与编辑页内的四个页签页，原先各自由屏幕或编辑页持有的「宿主适配接口」取状态：五个接口、约 223 行逐方法委托，形成 页 → 页签组合 → 编辑页 → 屏幕 的三层转发链。

同一份事实被拆成两份副本：屏幕用模式枚举与当前编辑目标表示「正在做什么」，页实例是否为空另行表示同一件事，于是同一判断散布在 40 处模式分支与 27 处空页守卫里。底部提示则靠色值在页与屏幕之间传递，颜色被反解成级别，成功色与次要文字色都落到操作回执，页里还出现直接调用屏幕静态取色方法的越层调用。

## 决策

1. **新增编辑器外壳**：外壳拥有当前编辑目标、由目标派生的编辑会话、底部提示、可编辑判定与跨页命令。屏幕只保留游戏屏幕生命周期、布局、绘制与输入派发，不再缓存外壳已拥有的状态。
2. **外壳持有页面实例并成为命令路由入口**：管理页、编辑页、调试页与编辑页内的四个编辑分区都由外壳创建与持有，页的打开、返回与刷新由外壳命令完成。保存编排与本地校验仍留在页层，外壳只路由，不复制其判断。
3. **活动页是唯一真相，屏幕按页多态派发**：三种页实现统一的页接口（渲染、提示、输入与生命周期），屏幕对活动页派发，不再以模式枚举加空页守卫描述同一件事。
4. **提示以级别表达**：页与外壳之间只传递提示级别（操作回执、成功回执、需要留意、失败或危险），形态、用色与停留时长由渲染决定；页内不得出现调色板色值。
5. **外壳的接口只表达编辑语义**：页面在构造期直接取得稳定协作对象（规则模型、工作区只读视图、列表展示缓存、字体、弹窗栈、焦点管理器，以及由类型注册表派生、无状态的条件编辑支持）；外壳只提供运行期状态查询、跨页命令与实时尺寸。页可以直接查询规则模型，但推进编辑状态的写操作只走外壳命令。随编辑目标变化的状态（会话、编辑分区、页面实例）不属于构造期协作对象。
6. **页接口只覆盖派发面**：三种页共有的渲染、布局、页脚、焦点与输入方法进接口，命名与参数归一（页脚改传区域矩形；按钮刷新与作用域变化各收成一个方法；使能不走派发，见决策 9）；输入差异收进各自页内。页特有能力（保存、刷新列表、打开新规则、调试填充等）由外壳按具体页调用，不进接口。
7. **可编辑判定只提供状态查询**：外壳暴露纯查询的可编辑状态；冻结提示在可编辑状态翻转时统一发一次。页面在写入前只做查询短路，不再各自提示。
8. **页声明窗口排版度量**：窗口几何、标题带、提示带、页脚带与内容区仍由屏幕统一排版；页只声明自己的差异度量（头部高度、内边距）并提供页签条的布局与绘制入口。屏幕按度量排版后经页接口派发渲染与页脚，不再以模式枚举或页类型分支决定排版。
9. **使能状态由页查询**：可编辑状态只由外壳的查询提供；页在渲染与布局前读一次并同步自身控件使能。屏幕不再记录上一次的可编辑值，也不再向各页推送使能。
10. **反向动作由外壳收口**：焦点重建由外壳完成（焦点管理器与活动页的焦点目标入口都在外壳手里），页与屏幕调用同一处；关闭游戏屏幕不回调，外壳只记录关屏请求，屏幕在事件结束与每帧更新时查询并执行。外壳因此不依赖屏幕类型或渲染类型。
11. **页接口只额外开放三个可选入口**：覆盖层（可空，屏幕在内容区之上渲染并计入输入门槛）、说明提示（可空，悬停文本由屏幕绘制）、每帧更新（默认空实现，页内轮询留在页）。标签详情的点击优先处理并入页自己的鼠标处理。

## 考虑过的替代方案

- **保留五个宿主适配接口，只在页侧合并成一个**：接口数量减少，但命令仍回到屏幕执行，约 223 行委托只是换位置，屏幕继续兼状态主人。否决。
- **外壳只做状态门面，页实例仍由屏幕持有**：跨模式命令要触达页时仍需经屏幕，转发链保留，接口深度不变。否决。
- **外壳只持有模式枚举，屏幕沿用现有分支**：模式与页实例是同一件事的两份副本，三重条件与空页守卫都不会消失。否决。
- **维持三值提示级别，成功回执按操作回执呈现**：色值反解不可逆，成功色被降级为短暂灰字，且页仍需知道调色板。否决。
- **继续让色值充当页与外壳之间的词汇**：页必须查调色板，已经出现页调屏幕静态取色方法的越层调用；颜色是渲染细节，不是信息性质。否决。
- **让所有依赖都经外壳单入口转出**：外壳会膨胀成二十七个方法的透传门面，接口宽度追平实现，深度反而下降。否决。
- **把三页的全部能力并进页接口**：并集约四十个方法，每页都要实现与自己无关的方法，接口宽度追平实现。否决。
- **按能力拆成多个小接口、由屏幕查询组合**：类型判断从页接口搬回屏幕，接口更碎且没有减少判断。否决。
- **保留带提示副作用的冻结守卫**：同一次冻结会被多扇门各提示一次，而真正需要提示的只有状态翻转的那一刻。否决。
- **页自绘整窗**：提示带与页脚带的跨页一致排版会散成三份，且与「提示归外壳、由屏幕渲染」的决策冲突。否决。
- **屏幕按页类型分支排版**：只是把模式枚举换成类型判断，同一件事仍有两份表示。否决。
- **可编辑状态翻转时通知页**：为一个布尔给页接口加方法，而页本就在别处重算按钮。否决。
- **屏幕继续持上一次可编辑值并推送**：保留三份推送样板与一个屏幕字段，收益只是少一次查询。否决。
- **屏幕实现视图端口注入外壳**：焦点重建只需要焦点管理器与页接口，加一层端口只换来一次回调。否决。
- **页保留屏幕引用执行反向动作**：这正是本次要收掉的越层调用，且外壳无法脱离屏幕被驱动。否决。
- **外壳按具体页转发视图调用给屏幕**：外壳会重新长出视图方法，接口宽度推回屏幕。否决。
- **为标签详情单独加一个优先点击入口**：目前只有一个页需要；先并入页的鼠标处理，出现第二个同类需求再提取。否决。

## 后果

- 屏幕退回生命周期角色，新增页只需实现页接口并由外壳登记；页与页之间仍不互相引用。
- 外壳成为编辑器里唯一能推进编辑目标、提示与页切换的地方，探针只需对接这一个接缝。
- 保存编排、本地校验与列表缓存仍在页层；若外壳继续吸收这些职责，会重新长出第二个巨型类，评审时需要挡住。
- 页多态派发以三个编辑器页面的公共面为前提，公共面必须先于实现确定。
- 命名按层落地：顶层页实现 `EditorPage`，编辑页内的四个页签分区改 `*Section`，分区组合改 `RuleEditorEditSections`，活动页与提示级别收在 `EditorShell`；用户可见文案不变。
- 页的构造参数增加一组稳定协作对象；新增页必须声明自己需要的协作对象，不能靠外壳兜底取用。
- 页接口宽度锁定在派发面；新增一种派发动作要同时改接口与三页实现，这是有意保留的约束。
- 冻结提示只有一处来源；新增写路径只需查询可编辑状态，不再复制提示与去重逻辑。
- 页接口增加少量排版度量；新增页若排版与其它页不同，只需给出自己的度量，不改屏幕。
- 页在渲染前查询可编辑状态并同步使能；屏幕不再持上一次可编辑值，新增页也不需要额外的推送入口。
- 页到屏幕的反向调用归零；外壳不依赖屏幕类型与渲染类型，可由开发源集中的探针直接驱动。
- 页接口多出三个可选入口；新增页没有覆盖层、说明提示或每帧更新时返回空即可。
- 标签详情的点击优先级改由页内部决定，验收以实机点击标签条为准。
