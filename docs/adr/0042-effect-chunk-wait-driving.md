# ADR-0042：效果声明区块需求，由调用层驱动等待

- 状态：已实施。

## 背景

固定区域效果、动态落点和逐位置扫描都需要在区块不可用时保留断点。重试刻与等待标志由每个执行器维护，会让新增效果重复实现调度逻辑，也使预算续接、正常间隔和区块等待依赖额外状态才能区分。

## 决策

效果执行状态通过固定需求声明或推进结果提交本步所需区块。推进结果明确区分完成、预算续接、正常延时与区块等待，调用层负责检查、排期、连续等待窗口和终态通知。随机目标、扫描游标和真实完成量由效果执行状态持有，就绪后继续同一次执行。共享游标的当前需求替代已经失效的旧断点请求。契约见 [契约层核心](../modules/core-contract.md)，驱动行为见 [转化运行时](../modules/conversion-runtime.md)。

等待判断可以复用，终止决策由业务所有者保留：效果超时终结，催化剂门槛超时中止结算，持久返还沿用退避和账本恢复。该分工保留 [ADR-0023](0023-triggers-fixed-cost-and-complete-group-settlement.md) 的库存与中止语义。

## 考虑过的替代方案

- 仅提取重试工具：执行器仍需同时维护返回值、等待标志和重试刻，新增类型仍可能遗漏接线。
- 执行前一次检查整个效果的最大范围：扫描和动态落点会等待尚未访问的区域，范围知识也无法完全由调度器推导。
- 由等待驱动重放整步：部分写入与随机结果已发生，重放会重复产出或改变目标。

## 后果

新增效果只声明实际访问范围并保留业务进度，等待策略集中维护。自定义跨 tick 执行状态按明确的推进结果实现并重新编译；同步执行器沿用默认适配。区块就绪是本次推进的检查结果，跨 tick 续接时重新检查。
