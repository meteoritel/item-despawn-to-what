# ADR-0044：规则启用状态分层为内容默认值与本服状态

- 状态：已实施。
- 影响面：`core/model/Rule`（`enabled` 字段的语义）、`core/load/RuleLoader`、`RuleMerger`、`RuleFileParser`、`RuleSourceIndex`、`core/service/RuleSnapshotAssembler`、`RuleSubmissionValidator`、`RuleOverlayWriter`、`core/state/RuleEnableState`、`RuleEnableApplyService`、命令层；`core/network/protocol/RuleSnapshotEntry` 与 `RuleEditProtocol`；客户端 `client/edit/EditSession`、`client/edit/EditorChangeSet`、`client/edit/draft/PersistedDraft`、`client/ui/screen/RuleEditorModel`、`RuleEditorListActions`、`RuleEditorListPage`、`RuleEditorEditPage`、`RuleEditorInfoPage`、`RuleListDisplayCache`。
- 相关：三层作用域与覆盖合并见 [ADR-0014](0014-three-layer-scope-and-overlay-merge.md)；来源目录与覆盖层合并语义见 [ADR-0020](0020-source-catalog-and-overlay-merge.md)；术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## 背景

`enabled` 一度同时承担「作者希望默认是否启用」与「当前存档里是否生效」两种语义。数据包基底不可写，基底规则的启用状态无法在不改内容的前提下按存档切换；用覆盖控制条目表达停用，又把控制面塞进内容层：控制条目不携带内容却要占用覆盖层文件，快照里出现被注入 `enabled=false` 的伪内容，条目来源在「只读」与「可写」之间摇摆，删除遮蔽还要额外回收文件。

## 决策

1. **默认启用**：`enabled` 字段的语义收窄为「默认启用」，属于规则内容，随内容保存；它表达规则作者希望的默认状态，不决定某个存档里规则是否生效。
2. **本服启用状态按存档保存**：以规则 id 为键记录启用覆盖，缺席表示继承默认值。状态不写规则文件、不占覆盖层条目，随存档移动，不随服务器配置移动。
3. **生效启用 = 本服覆盖 ?? 默认启用**：加载时把生效值注入运行时规则对象，不修改规则 JSON 副本；快照、导出与复制看到的内容始终是规则文件内容。
4. **快照分开下发三值**：默认启用、生效启用、是否持有本服覆盖分别下发，客户端据此区分「默认关闭」「本服关闭」与「继承默认」。列表行按生效状态显示，停用条目整条置灰；只有存在本服覆盖时才附加「（本服）」标注，不存在「（默认）」一类后缀。
5. **废除覆盖控制条目**：`disabled` 与 `delete` 两种控制条目整体移除，屏蔽状态不再存在；覆盖层条目只承载普通规则内容，加载、解析、校验与保存链路不再识别控制字段。
6. **启停与内容编辑权分离**：能否编辑内容与能否启停是两个独立能力；内容只读的条目照样可以启停，启停不写规则内容、不要求覆盖层副本。界面提供本服启用开关与恢复默认按钮，命令 `/idtw rule <id> enable|disable|default` 提供同一能力。
7. **同批提交与统一回扫**：启停切换先落客户端本地意图，点「应用」时与内容修改一起提交；服务端整批接受或整批拒绝，随后重建规则索引并回扫全部维度。启停不推进内容保存的乐观并发版本。
8. **孤儿状态保留并忽略**：状态层里已无对应规则的 id 保留并忽略，提供查看与清理入口，不在加载时静默回收。
9. **恢复默认与设为默认值区分**：恢复默认删除状态记录、回到继承默认；把本服状态设成与默认相同的值仍是一条显式覆盖记录。

## 考虑过的替代方案

- **继续用覆盖控制条目表达停用**：控制面留在内容层，数据包条目仍要靠写覆盖文件才能停用，快照里出现伪内容，删除遮蔽还要回收文件。否决。
- **把启用状态写进 server.json**：配置按服务器而非按存档，复制或回滚存档会带上错误的启用状态。否决。
- **只保存在运行时内存**：重启即丢，客户端也读不到权威值。否决。
- **在快照里过滤掉停用规则**：索引与匹配仍按旧值运行，界面与行为不一致。否决。
- **加载时继续往 JSON 副本注入 enabled**：快照生效视图、导出与复制会看到规则文件里不存在的字段，保存时有把注入值写回的风险。否决。
- **每次启停都完整重读数据包**：成本与内容保存同量级但不必要，沿用现有的重建索引路径即可。否决。

## 后果

- 界面上「默认启用」与「本服启用」必须同时可见、可区分，单开关无法表达两层语义。
- 导出的规则文件只含默认启用，与运行时生效状态可能不同；需要按存档阅读的场合应以本服状态为准。
- 控制条目相关代码路径、校验分支与 `MASKED` 状态整体退出，覆盖层只保留普通规则。
- 快照协议字段与协议版本随之调整，客户端与服务端按协议版本协商后使用新字段。
