# ADR-0061：kit 原版默认主题与宿主统一换肤

- 状态：已实施；当前接入见 [UI kit](../modules/ui-kit.md) 与 [客户端界面](../modules/client-ui.md)。
- 依据：独立通用库目标，以及宿主一次调用替换整套主题的使用需求。

## 背景

通用 GUI 库需要开箱可用的控件外观；Minecraft 原版 sprites 是可随资源包复用的默认来源。项目正文、画布外壳与业务图标具有自己的视觉语义，由宿主组合。存量输入、模态与浮层需要在保留编辑状态的同时更新外观。

## 决策

1. kit 提供完整原版默认主题与通用主题契约，统一控件、通用语义表面、滚动、选择、焦点、tooltip 和带皮肤屏幕。默认窗口使用半透明渐变外壳，按钮和滑块复用原版 sprites；项目业务配色和业务图标由宿主适配。
2. 每个 UI 根持有稳定主题上下文，子控件共享来源，以 revision 刷新皮肤与度量缓存。编辑模型、文本历史和视图状态由原控件持有。
3. 客户端选择所有者只保存稳定方案标识；公共外观按钮请求当前/原版完整方案，根在输入派发结束后的准备点发布正文与外壳主题，再刷新布局和同步作用域。指针捕获期间只保留最后选择，在原手势正常释放后应用；关屏和切域继续按输入所有权结束会话。重复选择保持 Context revision。显式控件覆盖优先于主题默认项。

## 考虑过的替代方案

- 宿主独占通用窗口和表面画法：独立库的默认屏幕仍要求宿主补齐外壳，且通用皮肤在多个宿主重复实现，否决。

- 每个宿主手写全部主题：基础接入重复承担原版外观装配，否决。
- 全局可变主题：独立屏幕与宿主难以保持各自外观和资源所有权，否决。
- 换肤重建 Screen：编辑状态、焦点、历史与浮层需要跨实例迁移，否决。

## 后果

- 默认主题与宿主 adapter 共同消费同一主题契约，主题变更集中于根与控件缓存；表面与 tooltip 以完整 skin 配套颜色和画法，业务图标按用途解析。
- 原版贴图替换通过资源管理器生效；原版类型和通用渲染能力随 kit 维护。
- 宿主负责业务视觉、主题方案和根生命周期，kit 负责通用控件的默认外观与版本响应。
- 宿主通过基底快照组合差异，按颜色组、角色皮肤、资源映射、painter 或度量替换外观；带皮肤屏幕直接复用注入的 Context，根发布队列可在同一准备点更新正文与画布外壳。
