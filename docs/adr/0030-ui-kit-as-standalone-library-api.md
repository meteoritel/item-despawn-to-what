# ADR-0030：UI kit 定位为可独立发布的库 API

- 状态：已实施；kit 依赖边界与公开面见 [UI kit 模块文档](../modules/ui-kit.md)。
- 依据：kit 的库化目标，以及用户对「kit 内零引用公开类去留」与「通用能力归属」的答复。

## 背景

kit 由 [ADR-0022](0022-client-ui-kit-adoption.md) 同源引入、按 [ADR-0025](0025-reusable-client-ui-kit-boundary.md) 作为记录来源与差异的维护副本。kit 不依赖本模组其它包、不依赖加载器 API，边界由 `tools/check-ui-kit-boundaries.ps1` 强制。但 kit 内同时存在两类内容：可被任意宿主复用的通用能力，以及只有本项目才用到的实现；同一能力若在宿主控件层另行实现，两处会分叉（滑块与区间条核心、换行布局即属此类），kit 中另有当前没有生产调用点的公开类。

kit 未来要独立成库，必须先确定「什么进 kit、什么留宿主」，否则每次能力扩张都要在两类内容之间重新解释。

## 决策

1. **kit 按可独立发布的库 API 维护**：与项目业务无关的布局、交互、绘制原语在 kit；业务控件、屏幕、主题、文案与目录协议适配在宿主侧。
2. **通用能力上提、宿主不再另行实现**：同一能力只保留一份实现，宿主控件调用 kit API，而不是另行实现。
3. **kit 零引用的公开类不留悬空**：确认为对外公开 API 则登记进公开面，否则删除。
4. **当前在本项目内开发与测试**：不从 `settings.gradle` 拆出独立模块、不发坐标，边界由脚本强制，公开面由 [UI kit 模块文档](../modules/ui-kit.md) 登记。

## 考虑过的替代方案

- **立即拆成独立 Gradle 模块并发布坐标**：接口仍在演进，过早固化会把本项目节奏绑在版本兼容上。
- **继续把新增通用能力放在宿主控件层**：拆库时仍需二次搬迁，重复实现继续分叉。
- **对零引用公开类不表态**：公开面无法核查，拆库时必须先补一轮去留裁决。

## 后果

- 新增控件的落点先判断「通用 / 本项目专用」：通用能力进 kit，专用能力进宿主侧。
- kit 公开面变化需要登记，边界脚本是唯一强制校验。
- 独立库的 package、坐标、版本与许可另立任务；当前未拆出独立 Gradle 模块。
- 宿主侧不再保留与 kit 重复的实现。
