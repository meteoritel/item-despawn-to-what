# ADR-0057：预览场景按可见性准备并短期驻留，统一方块转台

- 状态：已实施。

## 背景

图标展示覆盖物品、方块、流体、实体、方块实体与客户端结构资源。目录与规则需要共享取景、着色、失败状态和资源生命周期；方块、方块实体与实体需要一致的转台，首次展示和短期重复打开需要稳定的视觉反馈。

## 决策

1. **统一为主体、场景、视图三段契约**：主体表达展示内容，场景持有准备结果与模型包围，视图负责适框、旋转、深度、裁剪、光照与绘制状态恢复。宿主把目录条目、规则参数与结构资源转换成主体，所有这些预览经同一门面生成图标。kit 消费展示数据，文案与业务解释归宿主。
2. **统一入口内保留三种绘制路径**：物品复用原版 GUI 物品绘制；方块与流体缓存静态几何；实体与方块实体复用实例并逐帧调用 renderer。结构组合静态几何、方块实体与实体列表。烘焙只针对静态几何。
3. **结构图标使用运行时场景绘制**：结构资源随本模组客户端 assets 分发，由资源管理器读取。几何准备后缓存，整体模型变换驱动转台；相同内容在不同目标矩形中共享场景资源，资源重载统一失效。结构资源只需维护 NBT，图标由同一场景入口生成。
4. **预览后端归 kit 的 preview 子包**：沿用[可复用 kit 边界](0025-reusable-client-ui-kit-boundary.md)与[独立库定位](0030-ui-kit-as-standalone-library-api.md)。依赖方向为 preview → kit 基础类型；基础类型通过既有绘制回调承接图标。公开面只暴露宿主需要的主体、准备与绘制契约，几何缓冲、剔除算法与预算实现保持包内可见。
5. **线程与资源由明确的所有者管理**：资源解码与静态几何编译使用宿主注入的 Executor；实体和方块实体实例准备、renderer 调用、GPU 上传与释放在客户端渲染线程执行。kit 持有场景资源并提供预算推进与关闭入口，宿主接入资源世代与界面生命周期。
6. **方块实体保留状态与载荷**：单方块主体携带 BlockState 与可选方块实体 NBT，结构保留逐格方块实体载荷；实体保留 NBT、局部位置与朝向。预览实例独立持有、不加入真实世界、不 tick。静态几何的只读占位视图与 renderer 所需的 Level 上下文分别处理；需要 Level 的场景使用当前客户端世界，缺少上下文时给出明确状态。
7. **稳定取景与类别动态策略**：方块、方块实体和实体共用转台周期与相位，结构使用独立周期；物品与流体默认静态。整圈旋转共用适框尺寸，周期、初始角度与时钟由宿主提供。预览使用满亮和固定草、树叶、水着色。
8. **邻面与外部可达性剔除默认开启**：完整占位数据供邻面、AO 与着色读取，剔除仅影响静态几何提交。遮挡按 isSolidRender 判定，透明或非完整方块保持连通；相机旋转复用同一份几何。
9. **半透明随视角更新排序**：保留排序所需的 quad 中心与索引类型，旋转改变视角时重建并上传排序索引；顶点几何复用。图标采用角度档控制更新频率，排序依据预览视角。
10. **预算按实际资源量记账**：静态几何按顶点与索引实际字节计入总预算，默认总量 32 MiB、单场景 8 MiB；超出总量按最近使用淘汰，超出单场景给出明确状态。编译、待上传数据与上传推进均有边界，防止排队结果绕过驻留预算。
11. **可见性决定准备顺序**：实际绘制优先使用共享逐帧预算，帧末剩余预算推进邻近预取。宿主只登记可见行及相邻行，轮播只预热当前与下一成员；过期准备请求退出队列。准备中用中性占位，失败保留独立标记。
12. **关屏保留近期就绪内容**：宿主只短期保留最近展示的 READY 场景，场景数、renderer 实例数与几何内存分别受限；超时、世界或模型资源世代改变时释放。未完成任务的晚到结果释放并归还预留账目，后台编译退出前仍占用待上传预算。
13. **加载与失败是统一状态**：准备中的场景、空内容、缺失主体、缺少世界上下文、超限与失败分别表达；宿主负责本地化与占位图标。失败缓存随世代失效，诊断保留具体资源和原因。

## 取舍

- 可见项优先和小范围预取在既有预算内缩短等待；短期驻留减少重复打开的冷启动，统一注册表全量预热会增加无关准备与内存占用。
- 原版物品绘制复用既有外观与物品专用 renderer；三维场景共享取景与生命周期，避免为每类对象复制样板。
- 运行时结构场景直接满足图标旋转与资源重载需求，维护对象是结构 NBT；静态 PNG 需要额外资产生成与同步流程。
- 缓存静态几何把旋转成本集中到绘制与半透明排序；按实际字节控制缓存比按结构最长边推断几何成本更直接。
- 以图标为交付范围，放大窗口交互、平均色体素化、离屏光栅缓存和放置形状动画由独立需求处理。放置形状的表达约定为业务提供有序格子、视图提供进度。
