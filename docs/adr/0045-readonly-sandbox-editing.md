# ADR-0045：只读条目改为沙盒编辑

- 状态：已接受（尚未落地）。
- 影响面：`client/edit/EditSession`（只读门禁与撤销 / 重做拒绝）、`client/edit/TypeEditorDescriptor`（只读回退描述符）、`client/ui/screen/RuleEditorModel`（只读判定、草稿日志与变更集过滤）、`RuleEditorListActions`、`RuleEditorListPage`、`RuleEditorEditPage`、`RuleEditorScreen`（模式标识与页面使能）。
- 相关：启用状态分层见 [ADR-0044](0044-rule-enable-state-layering.md)；客户端草稿与编辑会话见 [客户端编辑器](../modules/client-editor.md)；术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## 背景

只读模式目前是一枚贯穿服务端快照、客户端模型与控件层的布尔：只读条目在列表页与编辑页被逐控件禁用，`EditSession` 在字段写入、撤销、重做与待定输入四处分别兜底拒绝；只读条目不能落草稿，也不能启停。只读的实际含义是「内容来源不可写」，实现成了「条目不可操作」——启停这类控制面能力被误伤，控件禁用又让用户无法在只读内容上试验修改。

## 决策

1. **只读只约束内容**：只读指条目内容来源不可写（内置数据包与世界数据包基底），不表示条目不可操作。
2. **不禁用编辑控件**：编辑页对只读条目开放全部内容控件，改动只存在于当前会话内存，形成沙盒。
3. **沙盒不落草稿、不进变更集**：沙盒改动不写入草稿存储、不计入脏标记、不参与保存与「应用」；保存与应用按钮按脏标记判断。
4. **离开即丢弃**：返回列表、切换条目或关闭界面即丢弃沙盒改动，再次打开看到服务端内容。
5. **模式标识替代控件禁用**：只读模式在编辑页右上角以加宽的状态标签直接呈现，文案含「只读 · 改动不会保存」这类说明；列表页在数据包条目右侧标注只读，不在控件旁逐项标注。
6. **启停与删除分开**：启停对所有条目可用（见 [ADR-0044](0044-rule-enable-state-layering.md)）；删除只对覆盖层条目可用，内容只读条目的删除入口不可点。
7. **撤销与重做保留**：沙盒内的撤销 / 重做照常工作，只影响会话内存，不影响持久层。
8. **复制作为出口**：只读条目可把沙盒内容复制为新规则，结果成为新的覆盖层条目，这是沙盒改动的持久化方式。

## 考虑过的替代方案

- **保留逐控件禁用**：只读条目无法启停、无法试验；门禁散落在会话、模型与页面多处，容易漏。否决。
- **允许编辑但保存时静默丢弃**：没有模式标识时用户会以为已保存。否决（标识与丢弃必须同时成立）。
- **只读条目只做只读预览**：复制前连临时调整都做不到，逃生通道变窄。否决。
- **沙盒改动先落草稿存储再由服务端拒绝**：草稿会跨会话残留，只读条目会出现在「未完成」分组里。否决。

## 后果

- 只读判定从「能不能操作」收缩为「内容能不能保存」，内容面与控制面的按钮使能规则分开维护。
- 会话层门禁消失，只读约束收敛到草稿存储与变更集两处。
- 沙盒改动关闭界面即丢失且不弹确认，只读模式标识是唯一提示，必须始终可见。
- 草稿存储不再出现只读条目，冲突恢复只处理可写内容。
