# ADR-0055：输入作用域统一拥有持续交互与焦点

- 状态：已实施；当前接入契约见 [UI kit](../modules/ui-kit.md) 与 [客户端界面](../modules/client-ui.md)。

## 背景

页面、模态与复合控件同时需要处理输入归属、持续交互结束和焦点恢复。让宿主逐类派发、让每个控件持有独立捕获，都会把同一条生命周期分散到多个所有者；普通失焦、取消和业务激活也容易混在一起。kit 在本项目内开发与测试，需要以统一契约完整迁移消费者。

## 决策

1. 宿主选择稳定的输入作用域，kit 实例路由器负责切换和通用派发。输入与 hover 使用同一活动作用域；命中沿内容树完成，焦点政策读取实际叶子报告。
2. 每作用域拥有一个持续交互会话和一个逻辑焦点。会话区分指针、键盘重复与精确文本；结束先摘除所有权再通知，值快照与手势数据留在控件模型。
3. 普通同域转焦完成有效数值编辑，Esc、切域及控件失效取消未完成预览。非法文本保留原文和错误、回退数值预览并允许离开；合法空端点按值模型提交。
4. 焦点能力、逻辑焦点、键盘轮廓、激活动作与业务选中分别表达。轮询入口不参与焦点；分面整组一个 Tab 位置，组内导航后由 Enter/Space 激活。覆盖作用域退出后恢复合格的旧焦点，交互不恢复。
5. 当前消费者和装配示例直接使用统一契约，被替代的捕获、派发与兼容入口随迁移移除。

## 考虑过的替代方案

- 宿主保留多套派发和清理分支：同一输入政策需要在页面、模态与复合控件中分别维护。
- 控件继续独立拥有捕获，作用域仅广播取消：持续输入的实际归属仍有多份答案，迟到释放和焦点变化继续依赖宿主配合。
- 把文本、数值与手势快照也收入统一会话：会话将依赖端点缺席、原始文本、滚动和平移等不同模型；所有权集中、具体值模型独立更贴合当前职责。

## 后果

新增持续交互接入所属作用域，隐藏、禁用和局部卸载结束具体目标；作用域切换由路由器收束。复合控件的私有编辑模式使用唯一焦点管理器和外部 Tab 锚点。旁白、自动滚动与宿主历史作为作用域回调注入。
