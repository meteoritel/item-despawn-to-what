# ADR-0041：输入门槛与实际消耗统一归规则结算

- 状态：已实施；实现见[规则模型](../modules/rule-model.md)、[转化运行时](../modules/conversion-runtime.md)与[规则加载](../modules/rule-loading.md)。

## 背景

门槛描述启动所需库存，实际消耗描述每轮支付量，两者需要独立调整。将材料支付作为结果行为会让输入准入、支付时机和源库存守恒分散在不同执行路径，且容易混淆门槛与消耗。

## 决策

源物品以规则源成本表示每轮门槛与消费上限，缺省为 1。源实体整堆交给结算，实际源占用与未消耗返还遵循 [ADR-0043](0043-result-budget-and-source-settlement.md)。催化剂以一个规则对象分别承载逐引用门槛、实际消耗和共享半径；开启消耗时以当前门槛作为消耗初值，之后两份数量独立编辑。条件叶可保留自己的数量声明：投影时叶上已声明的数量优先，留空才按规则门槛补齐，半径统一取规则的共享半径；实际消耗不参与门槛解析。

流体存在判定同时接受源与流动流体。规则开关控制是否在每轮开组前支付真实源，沿接触流体的液位与下落状态反向追溯，并选择最近可对应源。搜索受公共预算与有限访问量约束，避免单次扫描占满服务器 tick。

结果效果只描述产出与世界动作。每组统一复核门槛、支付能力与流体路径，再连续提交催化剂与流体扣除，源物品由结算按行为占用；不足时停止后续组并返还剩余源库存。

## 考虑过的替代方案

- 将门槛等同实际消耗：无法表达门槛较高、每轮少量支付的配方，否决。
- 在结果方案中保留材料支付：输入行为依赖候选方案且与准入分离，否决。
- 固定邻域内取最近流体方块：可能移除流动块或旁边无关水源，否决。
- 无界扫描流体网络：单次工作量与世界规模耦合，否决。

## 后果

规则输入是数量语义的统一来源，编辑器、校验、运行时与只读配方视图使用同一字段。契约使用严格解码，未知字段与旧写法按错误级拒绝；`schema_version` 声明非当前值时规则直接报错，用户数据不自动迁移。受限流体搜索找不到可确认源时本轮不开组。
