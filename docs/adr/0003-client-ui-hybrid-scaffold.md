# 客户端配置编辑 UI 采用声明式字段 schema + 自定义逃逸的混合脚手架

> 历史记录：本文绑定的旧实现已退役；当前后端契约与前端占位决定以 [ADR-0017](0017-backend-cutover-and-budgeted-effects.md) 和 [当前架构](../dev/architecture.md) 为准。

## 背景
为支持第三方转化类型的客户端编辑 UI，需在"客户端/服务端分离"约束下（服务端不得引用客户端类）提供一套客户端注册与渲染机制。现有 5 个类型均为手写 `FormSection`+`EditScreen`+`Presenter`，其中世界效果/方块含条件性 UI。纯手写对第三方样板过重，纯声明式又难以表达条件性 UI。

## 决策
客户端另设独立注册表（以同一 `ResourceLocation` 关联服务端 `ConversionType`），提供两条路径：
1. 声明式字段 schema（key / 类型 / 标签 / 校验 / 建议提供器）-> 框架内建表单渲染器自动生成表单，覆盖简单类型；
2. 自定义逃逸：复杂类型可注册自定义 `FormSection` / `EditScreen` / `Presenter`。
现有 5 个类型按复杂度拆分：简单类型迁至声明式 schema，世界效果 / 方块等保留自定义。

## 考虑过的替代方案
- **全手写（仅提供基类）**：权力最大但第三方样板最重，框架不收敛 UI 一致性。
- **纯声明式（无逃逸）**：样板最少但条件性 UI 难表达，世界效果这类无法支持。

## 后果
- 框架需内建一个支持条件性字段的表单渲染器（增量工作）。
- 客户端注册表与服务端注册表以 id 关联但不互相引用，严格遵守客户端 / 服务端分离。
- 现有 `FormSection` 部分需迁移至 schema、部分保留，迁移量中等。
