# 运行时：到期事件 + 分桶调度 + per-level 追踪状态

> 实施补充：本文的最新调度、区块生命周期、保存与前端边界以 [ADR-0017](0017-backend-cutover-and-budgeted-effects.md) 和 [当前架构](../dev/architecture.md) 为准。

## 背景
旧运行时每 20 tick 全量遍历追踪集合，用"通过条件的检查次数"计时（`conversion_time` 标称秒、实为检查次数），热重载对已存在的掉落物无效，追踪表是静态 `Map<ServerLevel, ...>` 强引用维度对象且从不清理（内存泄漏）。规则选择还依赖引用身份比较，重载后语义未定义。

## 决策
1. **到期事件语义**：触发时刻 = `min(trigger_after_seconds × 20, lifespan - 1)`，在原版 `ItemEntity` 自然 discard **之前**判定并拦截（原版没有"消失后"回调）。
2. **绝对存活时间计时**：不再用"检查次数"；条件不满足进入**退避重试** 1s → 2s → 4s → 封顶 `backoff_max_ticks`，到自然消失前停止。
3. **按 tick 分桶调度器**：入队/出队 O(1)；每 tick 执行数受 `max_checks_per_tick` 预算限制，超出部分顺延到下一 tick；单任务异常隔离，VM 级错误上抛。
4. **per-level 状态，不持有 `ServerLevel` 引用**：状态按 `ResourceKey<Level>` 索引；维度卸载 `clear`、服务端停止 `shutdown`；追踪状态只存内存、不写实体 NBT、重启即丢。
5. **reload 回扫**：规则热替换后重建索引并清空追踪，随后回扫已加载区块的 `ItemEntity` 重建追踪；标签与气候缓存一并失效。
6. **规则选择**：优先级 desc → 条件叶数 desc → 定义序；命中即执行该条规则的全部效果；彻底移除引用身份比较（快照失效则重选）。
7. **效果派发统一处理** `delay_ticks` / `chance` / 效果级 `conditions` / 隐式消耗 / 异常隔离；执行器只做世界操作。
8. 模组级参数集中在 `config/itemdespawntowhat/server.json`（检查间隔 / 退避上限 / 每 tick 预算 / 覆盖层目录 / Fabric lifespan 兜底 / 调试开关），文件缺失即落盘。

## 考虑过的替代方案
- **保留周期性全量遍历**：实现简单、行为可预期，但丢弃物数量上升时开销随"追踪数 × 检查频率"线性增长；分桶把开销摊到到期那一刻。否决（Q22）。
- **把状态写进实体 NBT**：可跨重启保留，但污染存档数据、与模组卸载耦合。否决（Q38）。
- **延迟任务持久化**：跨重启续跑需要落盘与版本管理，收益低。否决（Q38）。
- **条件不满足即放弃**：与"到自然消失前一直有机会"的直觉不符，且条件（如天气）会随时间变化。否决（Q12）。

## 后果
- 追踪数、到期任务数、每 tick 耗时都可通过 `/idtw debug stats` 观测（命令树交付后）。
- 性能验收改为可量化指标：1 万被追踪掉落物时 TPS ≥ 19.5 或检查开销 < 0.5 ms/tick（用户实测）。
- 运行时状态是"可丢弃的缓存"：重启、维度卸载、reload 都只影响追踪覆盖，不影响配置正确性。
- 气候采样位置缓存目前无容量上限，长赛季存在内存风险（记入阶段⑥ 清理项）。
