# ADR-0062：正式发布配置的版本迁移与文件所有权

- 状态：已实施。

## 背景

正式 release 的配置需要跨版本延续；开发中的中间格式由开发者调整本地数据。规则具有只读数据包与可写覆盖层两种来源，文件升级必须保持来源优先级、规则身份和既有文件所有权。

## 决策

兼容基线采用 `2.0.0` 的配置与规则结构，分别定义为格式 `1`。`server.json` 使用 `config_version`，规则对象沿用 `schema_version`；缺省版本固定为基线，新输出显式携带版本。格式版本只随持久数据解释变化推进，正式 release 记录对应格式版本，转换按已发布的相邻格式顺序执行。

共享纯 JSON 迁移 Module 负责严格版本识别、转换链和独立当前文档；配置与规则各自声明转换。当前 Codec 与业务校验消费当前文档，模型往返不承担迁移，原始字段和缺省含义由转换保留。

`server.json` 在装配前准备并安全写回。覆盖层在服务端初始化期间，经既有唯一文件队列按原始文件位置准备，成功文件备份后原子替换；本轮规则与编辑在迁移收尾后发布。文件版本支持重复初始化及部分文件失败后的再次处理。普通编辑保存保持整批提交语义，并写入同一份已经校验的当前文档。

数据包只迁移内存副本；不受支持的版本、转换失败及当前规则校验错误按既有文件/条目粒度拒载。编辑、来源恢复、持久草稿中的规则体和规则集合导出共享当前文档准备。当前格式导出产物仍是客户端生成的规则集合数据包。

本次覆盖配置、覆盖层初始化、数据包兼容、编辑保存和规则集合导出。存档状态、草稿包装格式、Minecraft 数据包格式与编辑协议分别由原有契约管理。完整原数据包升级工具、远程原包替换及第三方迁移扩展协议不进入本次实现。

## 考虑过的替代方案

- 全部旧数据包先拒载、要求用户更新：升级后规则立即停用，并需要额外的原包转换入口；选择共享转换后的内存兼容。
- 各读取和保存入口独立兼容旧字段：版本与默认语义分散，校验结果可能与最终写盘原文不同；选择统一文档准备。
- 以最后运行的 mod 版本决定迁移：共享目录和后加入的旧文件具有各自版本；选择文件格式版本作为转换依据。
- 从有效规则列表重建原包：合并已经丢失被遮蔽条目及其它资源；规则集合导出与完整原包升级分别定义职责。

## 后果

格式转换知识集中维护；I/O、线程、取消和提交由实际文件所有者掌握。升级前备份独立保留，写回失败但原文完整时可使用已验证内存文档；源文件状态无法确认时结束本轮模组装配。需要作者选择的语义变化以具体转换错误交付，避免静默改变规则行为。
