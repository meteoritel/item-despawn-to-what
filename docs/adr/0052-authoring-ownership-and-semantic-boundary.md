# ADR-0052：编辑生命周期所有权与语义传输边界

- 状态：已实施；实现入口见[编辑与作者链路](../modules/authoring.md)。
- 相关决策：[独占会话](0019-exclusive-edit-session-and-target-lock.md)、[进程文件队列](0037-cross-save-job-registration-isolation.md)、[按需来源视图](0040-on-demand-snapshot-source-views.md)。

编辑状态随一次服务端生命周期创建与退役，由 `RuleRuntimeHostCore` 持有的 `AuthoringHost` 装配。会话只持有独占归属与状态迁移；修订和文件工作归 `RuleOverlayStore`，目录缓存与传输状态归本次实例。唯一进程文件队列及停服超时退役继续遵循 ADR-0037，使跨存档的文件协调与单次编辑状态各有所有者。

业务服务与续接任务接收语义 Request、返回封闭 Reply，使用 `RuleAuthoringContext` 排期与发布；载荷、codec、文案映射、分片和交付节拍由 transport 持有。双端复用的编辑与目录模型直接归业务包，保留一份数据表达。业务输出不保存线上包，幂等结果也按保存语义记录，查询失败、保存终态与会话事件各自关联。

共同来源读取产出合并条目与同批分层索引。运行时发布和编辑磁盘视图分别按自己的读取点交接来源；来源查询可独立读取，快照缓存按内容修订和数据包上下文复用。命令详情直接输出胜出来源的原始 JSON；启停重建消费调用方本次来源，保留未知字段、来源优先级与内容修订语义。

`RuleEditChannels` 唯一声明方向、类型、codec、处理器与文本分片元数据，两个平台保持各自的注册与线程调度 adapter。客户端以连接绑定单一 receiver，延后回调核对捕捉的 Binding；服务端延后回调核对服务实例，生命周期更替不会把旧结果交给新实例。

## 取舍与后果

只在旧服务外增加 adapter 会保留业务对载荷与 codec 的依赖；复制整套 wire DTO 则增加两份模型的同步成本。直接迁移共享模型并集中线上映射，使依赖方向可由隔离脚本检查。目录接口的方法集合与语义保持，引用类型归 `core/catalog`；项目外 Java 实现需要按当前包重新编译。查询与会话事件的线上形状使用协议 10，客户端与服务端同步发布。

按路径懒建静态服务无法表达停服、同路径重开和旧回调的归属；统一服务端组合根与独立连接 Binding 各自解决其生命周期问题。分片元数据集中在声明而非另建通用注册框架，平台差异继续留在 adapter。
