# ADR-0035：运行时观测接缝

- 状态：已实施；观测实现与装配点见[编辑与命令模块](../modules/authoring.md)。
- 相关决策：[ADR-0024](0024-shared-server-tick-budget-scheduler.md)（观测对象包含排期句柄，替换观测实现不得改变调度语义）。

## 背景

转化运行时在关键节点需要上报观测：场景是否活跃、物品被观测到的事件、命中转化、候选结构、产物准备与产物落位，以及调试场景自行排期延迟任务。这些观测此前由运行时直接调用调试包中的实现类完成。

这使生产热路径硬依赖调试包：发布环境仍要编译并装配调试实现，调试关闭与否成为运行时内部判断，且「调试未启用」与「调试已启用但未开场景」两条路径的默认语义分散在各调用点，无法统一表述。

## 决策

1. **契约层定义观测接口**：接口方法全部为 default——判定类返回安全默认值、观测方法空实现、排期方法直接落到队列抽象。
2. **提供空实现常量、读取与注入**：`NONE` 表示未启用观测；读取入口返回当前生效实现；注入入口写入嵌套持有者中的 volatile 字段，装配期写入、运行期读取，替换对已启动的服务端线程立即可见。
3. **生产热路径只依赖契约**：运行时、效果执行器与类型层只引用契约接口；具体实现（调试观测实现）放在调试包，由两端平台运行时事件接线在装配期注入。
4. **未注入时的语义 = 未启用调试**：判定为不活跃、观测无副作用、排期走队列缺省路径。

## 考虑过的替代方案

- **运行时直接引用调试实现**：生产链路硬依赖调试包，发布环境无法在编译期隔离调试实现。否决。
- **每个观测点写一遍「调试是否开启」判断**：默认语义散落在调用点，热路径引入调试概念，且新增观测点必然重复这套判断。否决。
- **用事件总线或服务发现装配观测实现**：为单进程内的单点开关引入动态发现，启动期多出不确定性与失败面，收益不抵成本。否决。

## 后果

- 运行时不再 import 调试包；未注入实现时的行为确定，等价「未启用调试」。
- 新增观测点必须先扩契约接口并给出安全默认值，再在实现侧使用；观测实现不能改变调度语义（排期方法缺省即按队列原样排期）。
- 调试实现可整体替换：生产热路径只经接缝读取；替换实现只改动平台装配点与调试包自身，调度语义不变。
