# ADR-0058：箭雨按组结算并跨组合并为一次延迟任务

- 状态：已实施。
- 实现见：`core/type/effect/ArrowRainEffect`、`core/type/effect/exec/ArrowRainExecutor`、`core/runtime/SettlementArrowRainOutputs`、`core/runtime/ConversionSettlement`。
- 相关决策见 [ADR-0043](0043-result-budget-and-source-settlement.md)；效果参数见[效果](../wiki/zh-04-effects.md)。

## 背景

箭雨原先是一次性世界效果：同一源请求内每个槽位只尝试一次，容量探测对只含一次性效果的候选固定按一组处理。整堆源物品因此只演出一场，源库存与每组源成本对箭雨不起作用。箭雨本身不产出任何产物，不存在产物容量需求，一次性分支实际只起到「固定一组」的作用。

## 决策

1. **可重复世界效果**：箭雨不再声明为一次性效果。同一候选同一槽位按源库存与每组源成本各演一场，组数与其它效果同一口径，受催化剂上界约束。
2. **跨组合并**：同一候选同一槽位的多组请求在派发阶段合并为一份排期单，只注册一个效果任务；每组保留自己的到期刻、执行上下文与成功转化当刻抽取的药水效果。
3. **顺序执行**：该任务按组依次推进箭雨序列，一场打完后立即接下一场，全部场次结束才回执一次；推进所需区块跟着当前这场声明。
4. **不占产物容量**：箭雨不声明产出容量需求，不参与产出预算，`nearby_products` 对它不生效。
5. **成本与判定**：源成本仍按完整组在开组时消费，不按支退款；`chance` 判定与药水抽取从「整堆一次」变为「每组各一次」。

## 考虑过的替代方案

- **保留一次性，只把单场改成延迟任务**：不解决整堆只演一场的问题，源库存对箭雨仍然无效。否决。
- **每组各注册一个独立任务**：多组会在同一时刻各自写入，破坏「一场打完再打下一场」的观感，也让公共 tick 预算被同一效果的多个任务分摊。否决。
- **为箭雨声明产物容量需求**：箭雨没有产物，声明需求会错误占用邻近产物额度。否决。
- **新增世界效果场次上限配置**：规则侧已有 `count`、每组源成本与催化剂上限可调，新增配置只扩大调参面。否决。

## 后果

- 组数不再固定为 1：源 64 件、每组成本 1、`count` 为 32 时会连续打出约 2048 支箭，整体时长随场次线性增长。
- 一个合并桶共用一次区块等待上限：超时按失败终结该桶剩余场次，已写入箭矢的进度已经入账，不回退。
- 桶级回执与区块锚点归属首组，逐组进度仍记在各自组上，与方块批处理同一口径。
