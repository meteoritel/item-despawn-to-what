# ADR-0025：维护可复用客户端 kit，为独立 API 库准备边界

> 状态：已接受、待实施；用户于 2026-10-03 确认完整 GUI 计划与 kit 规格。
> 依据：[GUI 主计划](../plan/plan-gui-rule-update.md)、[kit API 规格](../plan/plan-gui-rule-update-kit.md)。

后端规则更新需要标量/区间/周期控件、目录网格与更完整的输入生命周期，而用户希望尽量复用并将 kit 未来独立为 API 库。继续维持 [ADR-0022](0022-client-ui-kit-adoption.md) 的冻结复制件、把新增能力全部放在业务 widget 中，会使交互和主题依赖继续混杂，之后拆库成本增加；立即发布外部库又会把尚在开发的接口过早固化。

决定将本仓库 kit 调整为**记录来源与差异的维护副本**：本期在明确输入、样式、事件和泛型数据边界后提取有实际用途的组件，宿主提供 Component、renderer、主题与业务适配。kit 保持 Minecraft 客户端通用依赖，不依赖本模组 core/edit/net/theme/widget、loader 或规则 JSON；规则命名、单位、目录协议、草稿与权限仍由宿主承担。

只替代 ADR-0022 关于永久机械改写与冻结副本的约束；同源来源、原始23文件清单、主题分层、平台隔离与来源可核查性继续成立。实施时在 NOTICE 中另记新增/修改、理由和回流状态，不伪造原提交的内容，不修改来源项目。独立库的 package、坐标、版本、许可与发布另立任务，本期不发布、不用绝对路径依赖来源仓库。

后果：基础输入与生命周期必须先统一，现有 widget 用必要适配逐步替换；公开接口需要示例和依赖审阅。接受这部分开发成本，换取后续复用与拆库时不携带规则业务；没有真实调用的抽象延后。
