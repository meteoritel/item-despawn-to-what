# ADR-0031：条件树编辑收敛为同一控件的两种渲染模式

- 状态：已接受；条件树与四页职责见[编辑器四页契约](../dev/internals/editor-pages-contract.md)。
- 依据：条件树双实现的实测结论，以及用户对「两套条件树控件是否合并」的答复。

## 背景

条件树有两套控件并存：缩进树控件在生产中只作只读展示，却保留完整的结构编辑、拖动与类型选择实现；画布图控件承担全部交互编辑。两者的增删、包裹、移动语义各写一遍，结构校验与问题类型也是两份，行为修复必须同步两处，漏改会出现「画布可用但树行不可用」。卡片内的缩进树同时还是条件叶参数编辑的入口，因此不能只删不补。

## 决策

1. **只有一个编辑入口**：条件树的结构与参数编辑全部经画布页完成，卡片内不提供就地编辑。
2. **缩进树降级为只读摘要**：卡片内缩进树只显示树干与叶条件名，并作为进入画布的入口，不提供结构编辑。
3. **两种渲染共用同一数据与校验**：结构校验与问题类型合一，渲染模式只决定展示形态。

## 考虑过的替代方案

- **删除缩进树**：失去卡片内的紧凑总览与进入画布的入口，条件叶只能从画布逐个寻找。
- **两套控件各保留编辑能力**：结构语义仍是两份实现，行为漂移与双份修复长期存在。
- **缩进树保留只读但独立校验**：问题类型仍是两份，展示与判定会再次分叉。

## 后果

- 卡片内条件树不可编辑，条件树编辑行为只有一处。
- 新增条件类型只需在共用的数据与校验上落点，两种渲染自动覆盖。
- 摘要区不再展示参数值，参数编辑通过画布完成。
