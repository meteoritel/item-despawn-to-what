# 配置引入 schema_version 与自动迁移

## 背景
`ConfigJsonCodec` 为纯 Gson + `@SerializedName`，无版本字段、无字段级迁移；Gson 默认静默忽略未知字段，且 `deserialize` 把任何解析异常 `catch` 成返回空列表（配置无声丢失）。`JsonConfigRepository` 仅有 ADR-0004 的路径级旧文件迁移，无字段级迁移。ADR-0007 的 DNF + 谓词/消耗拆分是对字段形状的破坏性变更，旧 v1 配置（扁平条件字段）会被 Gson 当作"未知字段忽略 + 新字段取默认值"，静默退化为无条件表达式（恒真）+ 无消耗的规则--非报错，而是行为静默错乱。

## 决策
`BaseConversionConfig` 增加 `schema_version` 字段。旧文件缺失该字段时由迁移器视为 v1（扁平结构），新建配置默认写出当前 v2。加载时按版本走迁移管线：v1 扁平条件 -> v2 DNF 单组 + 消耗指令拆分，迁移后写回 v2。同时修复 `deserialize` 静默吞异常（改为告警 / 拒读），未知字段不再静默忽略。

## 考虑过的替代方案
- **破坏性不兼容**：直接上 v2，旧 v1 配置被拒或静默清空。最简单，但现有用户配置丢失；叠加当前 `deserialize` 静默吞异常，风险更大。否决。
- **形状探测（无显式版本）**：靠字段存在性判断 v1/v2（有 `condition_expression` = v2，有扁平 `dimension`/`need_outdoor` = v1），迁移后写回 v2 形状但不带版本号。避免改文件外层结构，但未来再迁移缺版本依据、探测逻辑脆弱。否决。

## 后果
- 配置文件每条规则携带 `schema_version`；迁移代码为一次性，但需覆盖 v1 -> v2 全字段映射（5 个扁平条件 -> 条件叶、催化剂/流体的 consume 标志 -> 消耗指令）。
- 为未来 v3+ 迁移建立版本依据；`deserialize` 不再静默吞异常，配置错误将显式暴露。
