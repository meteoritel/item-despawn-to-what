# 代码风格：注释与常量

> 本文约束 Java 源码的注释、JavaDoc 与字面量处理。实现事实见各层开发文档；本文只回答「该不该写、写到什么程度」。

## 1. 注释与 JavaDoc

### 适用

- 适用于新增、修改、审查 Java 代码。
- 新增公开 class / interface / enum / method 必须有 JavaDoc，写明职责、用途、参数、返回值与异常；无对应内容时省略该标签。
- 注释解释设计原因与业务规则，不重复代码行为；不指向任何文档，避免文档更新造成死链。
- 修改代码时同步更新注释，不留过期说明与修改历史。
- 注释使用中文，技术名词保留英文。

### 判定

- 复杂逻辑：含多分支、嵌套循环、边界条件、状态转换、并发 / 事务或非直观算法时，必须有简短注释。
- 简单代码：自解释的 getter / setter、简单赋值、直接返回等，不写无意义注释。
- 过度注释：注释不增加设计、业务规则、边界条件或使用约束信息，视为过度注释。

## 2. 字面量：魔法字符串与魔法数字

- 业务逻辑中不直接使用缺乏明确语义的硬编码字符串或数字。
- 优先用有业务含义的命名常量、枚举、配置项或专用值对象替代硬编码值。
- 优先复用项目已有的常量、枚举与配置定义，不重复定义。
- 不机械提取所有字面量：按业务语义、使用范围、可维护性与可读性判断是否值得提取。
- 任何提取都保持原有业务行为与接口兼容。
