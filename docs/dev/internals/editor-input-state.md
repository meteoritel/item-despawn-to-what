# 编辑输入缓冲与配置历史

编辑器将已接受的规则 JSON 与未完成文本分开保存。`EditSession.snapshot()`、草稿落盘及提交协议只读取 JSON；输入文本仅在当前编辑会话中保留，退出并重新打开编辑器不保证恢复文本。

## 字段输入

`FormView.retainPendingInputs()` 将当前字段文本与校验问题保存到会话，不修改 JSON、不产生配置历史。单行、多行、列表条目、气候端点与物品数量输入使用同一生命周期；数量按引用键恢复，列表同时保存覆盖条目的下标。嵌套表单各自按绝对字段路径保存。

`FormView.commitPendingInputs()` 完成当前字段编辑，逐字段提交合法值。非法文本或缺失必需值保留在缓冲中；其它合法字段仍可提交。普通 `applyToDraft()` 跳过正在输入文本的字段，逐字符回调不会产生配置历史；Enter（多行文本除外）与字段失焦各完成一次字段编辑。没有 JSON 变化的完成动作不记录历史。

字段错误显示红色标记，悬停显示具体修正提示；气候错误定位到具体端点，数量错误定位到具体引用。范围条与时间条在叶参数面板中的精确编辑入口委托已有表单字段，使用同一套输入缓冲与错误定位。

## 页面生命周期

切页和返回前调用 `commitPendingInputs()`，卸载调用 `unmount()`。`unmount()` 只保存未完成文本和结束捕获，不再提交旧控件值。重建表单后 `reload()` 从当前 JSON 装载已接受值并恢复同路径缓冲。非法文本允许切页，保存前由 `EditSession.pendingInputIssues()` 汇总拦截。

`EditSession.revision()` 在规则 JSON 或历史恢复时变化。表单记录装载时的 revision；旧控件在卸载或重载前不会把旧路径文本覆盖到已恢复的会话状态，写入前会先重载当前代数据。

## 树结构操作与历史

树操作必须在 `EditSession.apply(opKey, change)` 的 `change` 内同步迁移或删除输入：

- `remapPendingInputs(Map<String, String>)` 同时迁移所有节点路径，支持兄弟节点交换，不顺序覆盖。
- `clearPendingInputs(scope)` 删除节点及其子节点的输入。
- `hasPendingInput(scope)` 查询指定条件表达式是否还有未完成输入，供源码视图提示使用。

历史条目保存 JSON、输入路径快照与结构操作的逆向路径映射。每份缓冲有会话内稳定 identity；撤销和重做恢复路径时保留该缓冲的最新文本。完成字段的缓冲在生成历史前移除，因此字段撤销不会用刚接受的文本覆盖撤销后的 JSON。结构变更后才产生的缓冲也按记录的路径映射移动；宿主必须提供所有受影响节点路径，不能用条件类型序号代替节点身份。

载入新草稿 `EditSession.load()` 清空输入缓冲与历史。配置历史保持每条规则独立；文本局部历史由输入控件管理，见 [UI kit API](ui-kit-api.md)。
