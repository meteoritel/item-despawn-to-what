# 抽象层：创作与管控（候选目录 · 编辑协议 · 命令 · 调试）

> 覆盖 `core/catalog`、`core/network`、`core/service`（编辑与会话部分）、`core/command`、`core/debug`。
> 类级细节见 [../backend/modules/edit-protocol.md](../backend/modules/edit-protocol.md)、
> [../backend/modules/command.md](../backend/modules/command.md)、[../backend/modules/debug.md](../backend/modules/debug.md)。

## 1. 这层解决什么问题

内核负责"规则怎么执行"，本层负责"规则怎么被写出、被管控、被观测"：
候选枚举（编辑器可选什么）、编辑通道（怎么安全地改规则）、命令（怎么查询与运维）、调试（怎么在开发环境验证真实链路）。

## 2. 候选目录层（`core/catalog`）

**两段式分工**，边界已冻结：

| 段 | 职责 | 不负责 |
|---|---|---|
| 数据源 | 按类别提供**全量**候选清单与内容修订号 | 分页、过滤、缓存过期 |
| 传输层 | 大小写不敏感的子串过滤（标识 / 展示名 / 副标题）、分页切分、按"类别 + 修订号"缓存与失效 | 权限与会话校验 |

- 候选类别为九类：物品、方块、实体、战利品表、群系、维度、标签、流体、状态效果。
- 数据源条目字段约定为标识、展示名、副标题与图标标识；图标仅物品与方块有值，其余类别由客户端走缺省渲染。
- **修订号必须与顺序无关**（基于内容哈希），内容未变时保持稳定，重载后内容变化即改变；否则客户端缓存会每 tick 误判失效。
- 数据源列表按服务端实例缓存；条目按修订号缓存。
- 新增候选类别只需扩展类别枚举并增加一个数据源，分页与过滤复用传输层。

## 3. 编辑协议与会话层（`core/network` + `core/service`）

### 3.1 协议数据模型

| 组件 | 职责 |
|---|---|
| 协议版本 | 握手不一致即拒绝；两端注册的版本必须对齐 |
| 编辑快照 | 规则来源三视图 + 问题清单 + 上下文修订号 |
| 快照条目 | 单条规则的标识、来源、状态、是否含内容、生效视图、数据包视图、覆盖层视图、问题 |
| 编辑变更集 | 乐观并发基准版本 + 有序的规则增删项 |
| 保存回执 | 状态码枚举 + 消息码与参数 + 结果版本 + 是否落盘 / 是否重载 + 问题清单 |
| 目录协议 | 分页请求与分页结果的类别、修订号、条目与末页标记 |
| 问题 | 结构化问题：严重级、规则标识、来源、字段路径、消息码与参数、兜底文案 |

**快照三视图语义**：

- `base` 为数据包层原始内容，`overlay` 为覆盖层原始内容，两者保留原文、不做模型往返；
- `effective` 优先取模型编码结果（解码成功时权威），失败时退回原始内容，保证客户端仍能展示；
- 状态取值为"生效 / 停用 / 被屏蔽 / 非法"；"是否含内容"只表示该条目存在规则内容，**不表示能否表单编辑**；
- 问题按来源与字段路径关联到具体条目，无法关联的问题作为快照级问题下发。

### 3.2 独占编辑会话

- **单一目标**：全局只有一个编辑目标，同一时刻至多一个非空闲会话；不按玩家分锁。
- **状态机**：空闲 → 取锁待确认 → 活跃 → 应用中 → 活跃；释放、租约到期、强制释放都回到空闲。
- **时钟**：一律使用服务端活动刻；单人世界暂停时租约不流逝；服务端周期性清理空闲会话。
- **职责切分**：会话状态机与版本戳、业务编排与幂等表、网络转发与权限检查分属不同组件；
  网络层只做"就绪 / 权限检查 + 发包转发"，业务编排只产出"要下发的载荷"，不直接触网。

### 3.3 服务端处理顺序与不变量

打开编辑器：权限与运行时就绪检查 → 原子取锁（唯一入口）→ 下发开屏载荷（**取锁失败也要下发**，客户端据此提示持有者）
→ 客户端确认（会话转为活跃）→ 请求快照。

请求快照 / 目录 / 提交变更集：会话持有与状态校验 → 心跳续租 →（保存路径）磁盘修订核对 → 业务处理。

| 不变量 | 含义 |
|---|---|
| 服务端权威 | 全部落盘经服务端；客户端只提交意图 |
| 乐观并发 | 变更集基准版本与会话版本不一致时**整批拒绝且不落盘**，并回最新快照 |
| 权威落盘 | 依据磁盘文件内容逐条增删改，保留未编辑条目、未知字段与非对象成员；控制条目与坏文件不被覆盖 |
| 整批语义 | 全部预备成功才逐个原子替换；任一失败逆序回滚；写入零文件或存在冲突都不算成功 |
| 幂等 | 同一操作标识的重复提交直接回放上次回执，不重复写盘 |
| 并发保护 | 仅在活跃态允许进入应用态；应用中收到新提交按无效请求处理并保留会话 |
| 路径安全 | 拒绝越界路径段与符号链接；同一标识多处定义直接拒绝，要求人工消歧 |
| 版本戳 | 成功重载与成功保存都推进版本戳；保存前与下发快照前都核对磁盘修订，无法核对时拒绝保存 |

### 3.4 分片与限额

- 变更集与快照都有直发上限、单片上限与总量上限；超限按 **UTF-8 字节**切分，不拆分代理对。
- 上行分片按传输标识重组，逐片校验、重复下标以首片为准，收齐后复核总量；每玩家并发在途传输数与空闲超时都有上限。
- 全部限额集中在一处契约常量，避免逐片、总量、并发、超时多处不一致；解码器保留余量，
  超限请求先落到服务端再回无效请求，不直接断连。
- 长度一律按 UTF-8 字节判断，防止多字节绕过上限。

### 3.5 作者可见性

新增规则字段与条件树结构通过两条通路自动进入编辑通道，**无需在协议层逐字段建模**：
快照侧下发覆盖层原始内容与数据包规则的模型编码结果；校验侧对每条上行的规则做完整契约解码 + 语义校验 + 动态引用校验，
任一错误即整批拒载，并附可定位到字段的问题。拒绝有损保存时**明确报错**，不静默兼容。

## 4. 命令层（`core/command`）

- 唯一根命令下分三个分支：配置（重载 / 打开编辑器 / 校验 / 列表 / 编辑锁）、规则查询（列表 / 展示）、调试。
- **根节点不统一鉴权**，权限下放到各子分支；权限口径为"单人世界放行，否则要求权限等级不低于 2"，
  与网络编辑会话的权限判定保持一致。
- 例外口径：编辑锁状态查询对所有玩家开放（不泄露会话标识）；强制释放要求权限等级。
- 一切玩家可见反馈都必须经统一的反馈构造出口使用本地化键，禁止在命令层写中文字面量；文案须同步中英两套语言文件。
- 命令层通过窄接口获取运行时能力（规则、配置、编辑上下文、覆盖层信息、活动会话数、重载能力）；
  需要新能力时扩展窄接口并由平台侧实现，而不是让命令层依赖平台运行时。

## 5. 调试层（`core/debug`）

- **仅在加载器开发环境启用**：发布环境不注册任何调试入口。
- **复用真实链路**：场景规则经真实的编解码、校验与候选索引构建，不是旁路实现；观察的是真实运行时回调；
  候选规则隔离（仅本轮登记的实体使用场景索引，其它实体回落用户索引），测试产物不进入用户规则链。
- **两种编排**：功能场景（声明式，单轮有界负载）与自动流水线（串行阶段计划、双时钟冷却、失败停止）。
- **有界样本**：测量样本有上限，满则停止，不伪造更长窗口；性能窗口同时计量原版与模组的 tick 成本与分项。
- **清理语义**：每服务器同时只允许一轮场景；停止时精确取消本轮任务并清理源与产物，**不清空普通队列**；
  流水线冷却期锁住场景入口。
- 场景与流水线由类路径下的声明文件与清单驱动，**新增场景无需改动命令树**。

## 6. 扩展点与约束

| 要做什么 | 落点 | 约束 |
|---|---|---|
| 新增候选类别 | 类别枚举 + 数据源实现 + 数据源登记 | 分页 / 过滤复用传输层，不要两处各写一份 |
| 新增协议载荷 | 协议类 + 两端注册器登记 | C2S 与 S2C 的**类型**都必须在公共初始化注册，否则专用服务端连接协商会判定通道缺失 |
| 改写盘策略 | 覆盖层写入器 | 保持"整批预备 + 原子替换 + 失败回滚 + 写入前核对未被改动" |
| 改快照形状 | 快照装配 | 保持覆盖层用原始内容、"是否含内容"的既有定义 |
| 新增子命令 | 命令分支 + 统一反馈出口 + 双语语言文件 | 需要新运行时能力时扩窄接口 |
| 新增调试场景 / 阶段 | 类路径声明文件与清单条目 | 不改命令树；测量样本必须有界 |
| 调整限额 | 协议限额契约常量 | 注意逐片、总量、并发、超时是同一组语义 |
