# 关键交互流程

> 四条端到端链路的抽象视图：规则怎么变成可执行索引、掉落物怎么被转化、规则怎么被安全写回、开发环境怎么验证真实链路。
> 涉及层次见 [architecture.md](architecture.md)；类级细节见 [backend/flows/](backend/flows/)。

## 1. 规则加载链路

**触发时机**：服务端启动、数据包重载、命令重载、编辑器保存后重建。四条路径共用同一实现。

```mermaid
flowchart TB
    A["触发：启动 / 数据包重载 / 命令重载 / 编辑器保存"] --> B["读取模组级配置（启动路径缺失时写出默认值）"]
    B --> C["构建内置类型注册表：条件 → 冻结 → 条件编解码 → 效果 → 冻结"]
    C --> D["读取三层规则来源：内置数据包 / 世界数据包 / config 覆盖层"]
    D --> E["按 id 合并：层内后者胜，普通条目先合并、控制条目后应用"]
    E --> F["逐条解码：补齐推导 id、注入停用标记、保留可定位的失败信息"]
    F --> G["结构档校验（不需要注册表）"]
    G --> H["参数档校验（需要注册表）+ 动态引用校验"]
    H --> I["构建候选索引：剔除不可运行规则、排序、门槛运行投影"]
    I --> J["清空追踪、置空依赖数据包的缓存、带原因取消旧任务"]
    J --> K["对全部已加载维度回扫已存在的掉落物"]
    K --> L["就绪：运行时按源物品查询候选规则"]
    D -->|"资源枚举失败 / 覆盖层目录不可读"| M["保留上一版索引继续服务，回报失败"]
    F -->|"单条坏规则"| N["拒载该条，其余继续；问题带来源与字段路径"]
```

**关键契约**：优先级为覆盖层 > 世界数据包 > 内置数据包；控制条目只在覆盖层合法；控制字段按取值判定；
规则标识在读取侧与写入侧的推导规则必须一致；校验必须使用"带注册表"的参数档，否则未注册类型与区间类非法参数会被静默放行。

**失败与边界**：单个坏文件只影响该条；枚举失败保留旧索引；重载不清空已提交的效果（只重建检查与索引）；
后加载的维度由维度加载事件补一次回扫；启动期的首次加载不按重载处理（此时维度尚未创建）。

## 2. 转化生命周期

```mermaid
flowchart TB
    A["掉落物入世界"] --> B{"排除判定：已移除 / 空 / 原版无限寿命 / 死亡掉落锁 / 已提交转化"}
    B -->|命中任一| Z["不追踪"]
    B -->|通过| C{"候选索引中是否有该物品的可运行规则"}
    C -->|无| Z
    C -->|有| D["建立追踪 + 首次排期：触发时刻取最早规则秒数与寿命减一的较小值"]
    D --> E{"触发来源"}
    E -->|自然消失| F["原版销毁前拦截：置到期接管标记，立即排一次检查"]
    E -->|火 / 岩浆 / 仙人掌| G["真实致死分支归类后请求转化"]
    F --> H["到期检查"]
    G --> H
    H --> I{"区块 ticking / 转化锁 / 永久禁转 / 转化冷却 / 候选非空"}
    I -->|不通过| J["退避重排（或结束追踪）"]
    I -->|通过| K{"逐条候选：声明该消失方式 + 年龄门槛 + 条件树四态命中"}
    K -->|未命中| J
    K -->|命中| L["整堆源转入结算库存 + 打已提交标记 + 写结算记录"]
    L --> M["计划：每组成本 × 可容纳组数；按组合模式选定一个候选"]
    M --> N["派发：逐组先支付催化剂、再扣固定源成本、记录组已开始，按定义序派发效果"]
    N --> O["交付：剩余库存作为返还物分批加入世界"]
    O --> P["结清记录；数量守恒：初始量 = 已消费 + 已交付返还 + 待交付返还"]
    M --> Q["中断：规则重载 / 维度卸载 / 停服"]
    N --> Q
    Q --> R["中止：同步待返还、记中断、释放未支付预留、写盘（不做世界写入）"]
    R --> S["恢复：下次启动或维度加载时只交付待返还库存，不重放已开始的组"]
```

**关键契约**：同一次检查只执行优先级最高的一条命中规则；年龄门槛只对非环境触发的自然消失生效；
环境致死请求在受伤调用栈内同步完成条件检查与规则选择；计划量不冒充成功量，真实完成量只来自执行器回执与进度上报；
概率落空、效果条件不满足、执行中途失败仍属已支付组。

**边界**：整堆源物品一次性转入结算库存，因此"被规则接管的掉落物"在结算期间不再以掉落物形式存在于世界；
目标区块未加载时不主动加载、带退避重试。

## 3. 编辑保存协议

```mermaid
sequenceDiagram
    participant P as 玩家
    participant UI as 客户端编辑界面
    participant SV as 服务端编辑服务
    participant LD as 加载与索引

    P->>SV: /idtw config edit（服务端先原子取锁，唯一入口）
    SV-->>UI: 开屏载荷（成功带会话标识；失败带当前持有者，客户端据此提示）
    UI->>SV: 确认会话
    SV-->>UI: 最新快照（来源三视图 base / overlay / effective + 问题清单）
    UI->>UI: 在本地草稿上编辑（撤销栈，字段级粒度）
    UI->>SV: 请求候选目录（类别 + 过滤 + 分页）
    SV-->>UI: 分页目录结果（按类别与修订号缓存）
    UI->>SV: 提交变更集（带乐观并发基准版本；超限按 UTF-8 字节分片）
    SV->>SV: 会话持有校验 → 幂等查表 → 磁盘修订核对 → 基准版本校验
    SV->>SV: 完整校验：解码 + 语义 + 动态引用（任错整批拒载，不落盘）
    SV->>SV: 基于磁盘内容原子写入覆盖层（备份、失败逆序回滚）
    SV->>LD: 重建索引并回扫全部维度
    SV-->>UI: 回执（状态码 + 结果版本 + 是否落盘 / 是否重载 + 问题）
```

**关键不变量**：服务端权威；乐观并发失败整批拒绝且不落盘；依据磁盘内容写入并保留未编辑条目与未知字段；
整批预备成功才逐个原子替换；同操作标识重复提交回放上次回执；版本戳在成功重载与保存后推进，快照下发与保存前先核对磁盘修订。

**状态分支**：落盘成功但重载失败时，回执会明确区分"已落盘、未重载"，并保留上一版索引；
运行时不就绪、无权限、会话失效、锁不属于自己都有独立状态码，客户端只按状态码分支、不解析文案。

## 4. 调试场景链路

```mermaid
flowchart TB
    A["开发环境：/idtw debug run | bench | pipeline"] --> B["读取类路径下的场景与阶段声明清单"]
    B --> C["用真实编解码与校验构建场景规则（来源标记为开发内存）"]
    C --> D["绑定本轮实体到该场景，候选规则按轮隔离"]
    D --> E["分批准备源与产物（受准备批量与准备预算约束）"]
    E --> F["预热"]
    F --> G["测量窗口：观察真实运行时回调，按计数键与实物校对预期"]
    G --> H["结束 / 停止：取消本轮任务并清理源与产物，不清空普通队列"]
    H --> I["输出结构化结论（IDEA 控制台单行日志，前缀固定便于过滤）"]
```

**关键契约**：场景复用真实链路而非旁路实现；测试产物的候选不进入用户普通规则链；
每服务器同时只允许一轮；测量样本有界，满则停止；流水线阶段间有双时钟冷却，失败停止后续计划。

**边界**：调试层只在开发环境注册，发布环境无任何入口；常规运行日志开关与开发场景开关是两回事。
