# 开发者与 AI agent 使用约定

> 本文是**约束集**：动代码前先读第 1 节，找落点用第 2 节，交付前走第 4 节。
> 分层与依赖见 [architecture.md](architecture.md)；链路见 [flows.md](flows.md)。

## 1. 硬约束清单（改代码前必读）

| # | 约束 | 含义 |
|---|---|---|
| 1 | **平台隔离** | 平台无关模块不引用任何加载器 API；平台专属代码只存在于两个平台模块中 |
| 2 | **端隔离** | 服务端路径不引用客户端类型；内核经静态 sink 触达界面，客户端未安装时为空操作 |
| 3 | **依赖倒置** | 内核不反向依赖平台运行时与客户端；平台能力只经平台能力契约、窄接口、静态 sink、注入点进入内核 |
| 4 | **模型不可变** | 规则及其子结构不可变，"修改"即构造新对象；集合对外为不可变视图 |
| 5 | **条件求值是纯谓词且四态** | 求值只读上下文、不修改世界；只有"命中"通过，"不可用"与"错误"一律不触发，取反不改变后两者 |
| 6 | **副作用只在效果执行** | 世界操作只发生在效果执行阶段，且只在服务端主线程 |
| 7 | **注册表注册期可变、冻结后只读** | 冻结后再注册或重复标识都抛异常，绝不静默覆盖；注册期只允许单线程写 |
| 8 | **编解码不产出空值** | 可空字段以可选值承载，末步回落；否则解码期直接失败 |
| 9 | **加载层与模型层单向** | 加载层不依赖模型层，模型以解码契约注入；装配层是唯一桥接点 |
| 10 | **旧格式零兼容** | 旧写法明确报错、不静默迁移；解码异常完整保留堆栈与可定位信息，不吞掉 |
| 11 | **失败保留旧索引** | 数据包重载或写盘失败不得让异常逃逸到事件回调，必须保留上一版规则继续服务 |
| 12 | **单条命中 + 完整组结算** | 同一掉落物每次检查只执行优先级最高的一条命中规则；成本按完整组支付；数量守恒；计划量不冒充成功量 |
| 13 | **共享预算** | 全服唯一一份每 tick 预算与唯一 tick 推进入口；长循环必须拆成有界步骤接入调度器，禁止另建第二份预算 |
| 14 | **实体状态存实体层** | 新产物保护、转化冷却、返还物禁转等状态记录在实体上，不随物品堆叠进背包 |
| 15 | **整体重建优于单点失效** | 与数据包相关的缓存与派生值随索引重建整体丢弃，不提供局部失效路径 |
| 16 | **不主动加载区块** | 规则执行不生成区块；区块不可用时退避重试 |
| 17 | **i18n 双语** | 所有 GUI / HUD / 命令文本使用本地化键，中英两套语言文件同步更新；命令文案只有一个统一出口，禁止中文字面量 |
| 18 | **禁止魔法值** | 业务逻辑中不得散落无语义的硬编码字符串与数字；优先复用既有常量、枚举、配置与值对象 |
| 19 | **调度预算参数需重启** | 预算类配置在运行时构造时读取一次，重载不重建调度器 |
| 20 | **Mixin 最小化** | 优先使用已有事件；确无等价事件才写 Mixin，且只作入口、业务放内核 |

## 3. 可依赖的对外面与不可依赖的内部面

**第三方与集成方可以稳定依赖**：

| 面 | 说明 |
|---|---|
| 规则数据格式 | 数据包内的规则目录与 config 覆盖层目录；字段契约见 [layers/server-core.md](layers/server-core.md) 与 [backend/modules/rule-model.md](backend/modules/rule-model.md) |
| 类型注册 SPI | 以服务发现登记的规则类型提供者；约束见 [layers/server-core.md](layers/server-core.md) §4 |
| 命令 | `/idtw` 命令树与其权限口径 |
| 模组级配置 | 固定的模组级配置文件位置与分组语义 |
| 客户端 UI kit | 声明的公开边界（尚未拆包发布，签名变更按变更记录走） |
| 候选目录协议 | 类别枚举与条目字段约定的冻结形状 |

**不可依赖（随实现变动）**：

- 内核内部包结构与非契约类型、窄接口的具体实现、平台接入层的内部细节、客户端控件层与屏幕层的内部结构、UI kit 的"内部实现"成员。

**新增网络载荷的两条硬规则**：C2S 与 S2C 的**类型**都必须在公共初始化注册；协议版本两端必须对齐。

**扩展类型的约束**：使用自有命名空间；编解码必须暴露完整字段集合；效果与条件不得注册到其它阶段；扩展包必须在服务端安装并满足加载器依赖声明。

## 4. 交付前验证流程

1. **静态检查**：先经 IDE 的语言服务检查本次改动的 Java 文件的错误与警告（忽略 Markdown 格式问题）。
2. **UI kit 边界检查**（仅当改动涉及 UI kit）：运行 `tools/check-ui-kit-boundaries.ps1`；
   退出码 0 表示通过、1 表示存在违规、2 表示配置错误（目录缺失或无源文件）。
3. **构建**：运行 `tools/dsh-build.ps1` 的 build 任务。该脚本内部有命名互斥，多个构建会排队；
   **不要裸跑 gradle 包装脚本**，以免与其它任务并行争抢同一构建目录。
4. **等待纪律**：构建等待不得短于 120 秒；若返回的是"运行中任务"，持续等待至结束；
   未确认上一次构建结束前不得重复启动。
5. **失败处理**：检查或构建失败时先修复并重新验证；原因不明确或修复需要改变设计时，停下来说明后再继续。
6. **验收边界**：构建通过与游戏内行为验收是两项独立结论；实机行为与性能由人类按 [debug/](debug/) 下的指南验证，不使用测试文件替代。

## 5. AI agent 使用约定

**进入项目时的定位顺序**：本文件 → [overview.md](overview.md) → [architecture.md](architecture.md) → 按任务读
[layers/](layers/) 与 [flows.md](flows.md) → 需要类与方法级细节时读 [backend/](backend/) 与 [internals/](internals/)。

**必须遵守**：

- 结论要能回到源码；推断与不确定处要显式标注，不得把猜测写成事实。
- 先确认改动落在哪一层，再动手；跨层改动先确认是否要拆分。
- 遵守第 1 节全部硬约束；尤其不要为单个用例开特例（如绕过鼠标释放归属、绕过共享预算、绕过整体重建）。
- 变更涉及玩家可见文本时同步中英两套语言文件。
- 只做被要求的改动；不改动无关文件与无关文档。

**禁止**：

- 让平台无关模块引用加载器 API，或让服务端路径引用客户端类型。
- 在条件求值中写世界、在效果执行外写世界、在调度任务里写超出单步上界的循环。
- 静默兼容旧格式、吞掉解码异常、以计划量冒充完成量。
- 为通过检查而弱化校验（例如把"整批拒绝"改成"部分通过"）。

## 6. 文档维护约定

| 文档类别 | 位置 | 应写什么 | 不应写什么 |
|---|---|---|---|
| 抽象层文档 | `docs/dev/` 根与 `docs/dev/layers/` | 分层、职责、接口契约、交互流程、扩展点与约束 | 代码片段、函数体、方法实现、逐条配置解释 |
| 实现层文档 | `docs/dev/backend/`、`docs/dev/debug/`、`docs/dev/internals/` | 包与类清单、方法级行为、逐项字段与常量、排查细节 | 与抽象层文档重复的分层叙述 |
| 决策记录 | `docs/adr/` | 为什么这样设计、被否决的替代方案 | 实现步骤 |
| 规范与计划 | `docs/spec/`、`docs/plan/` | 阶段性行为规范与设计概念 | 当作现行实现依据 |

约定：

- **单一来源**：同一事实只维护一处。类清单只在实现层文档维护，抽象层文档只引用不复述。
- **冲突以源码为准**：文档与代码不一致时，以源码为事实来源，并回改文档。
- **新增内容**：新增 `core` 子包或新的横切机制时，先判断它属于哪一层，再决定扩写现有层文档还是新开实现层文档。
- **入口唯一**：[README.md](README.md) 是本目录唯一的索引与阅读入口；新增文档必须登记进索引。
