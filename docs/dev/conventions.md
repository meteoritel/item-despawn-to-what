# 项目文档约定与阅读指南

> 本文只约束**本项目文档**：文档的层级与职责、维护与链接规则，以及 agent 阅读和理解项目文档的路径。
> 通用 agent 行为约束不在本文维护；代码与架构约束由各层开发文档承载，入口见 [README.md](README.md)。

## 1. 文档层级与职责

| 文档类别 | 位置 | 应写什么 | 不应写什么 |
|---|---|---|---|
| 抽象层文档 | `docs/dev/` 根与 `docs/dev/layers/` | 分层、职责、接口契约、交互流程、扩展点与约束 | 代码片段、函数体、方法实现、逐条配置解释 |
| 执行层文档 | `docs/dev/backend/`、`docs/dev/internals/` | 包与类清单、方法级行为、逐项字段与常量、配置与操作步骤、排查细节 | 与抽象层文档重复的分层叙述；修改历史与版本记录 |
| 决策记录 | `docs/adr/` | 为什么这样设计、被否决的替代方案 | 实现步骤 |
| 术语表 | 仓库根 `GLOSSARY.md` | 领域词汇、含义与 _Avoid_ 边界 | 实现细节、字段表、限额、状态与历史 |
| Agent 工作方式 | `docs/agents/` | 工作方式、任务载体、分诊口径、读取顺序 | 项目知识（由 `docs/dev/`、`docs/adr/`、`GLOSSARY.md` 承载） |
| 玩家 wiki | `docs/wiki/` | 面向终端用户的使用手册：玩法、规则 JSON 教程、命令用法、FAQ | 类名与包名、内部机制、开发流程、决策编号 |

## 2. 阅读协议

- **入口唯一**：[README.md](README.md) 是开发者文档唯一的索引与阅读入口。
- **先抽象后执行**：建立全局认知按 [README.md](README.md) §2.1 的顺序读抽象层；执行改动按 §2.3 的「任务 → 文档」路由定位**一篇**执行层文档，禁止一次性全量读取，需要相邻主题时沿该篇文末「相关」继续。
- **权威范围**：架构、职责与约束以抽象层为准；类名、方法行为、字段与常量的逐项事实以执行层为准。
- **冲突以源码为准**：文档与源码不一致时以源码为准，并回改文档。
- **符号定位不写行号**：引用源码用「类名 + 成员名」，行号会随重构漂移；临时审查文档为例外，允许在类名与成员名之外附**当前行号**作辅助定位，行号不作为长期契约。

## 3. 文档维护约定

- **单一来源**：同一事实只维护一处；类清单与字段表只在执行层文档维护，抽象层只引用不复述。
- **只写当前状态**：不得出现修改历史、变更日志、版本记录、日期注记，也不写「已废弃 / 已删除 / 已改为 / 旧实现」一类历史叙述；过期内容直接删除，不保留退役章节。
- **代码变更即同步**：改动功能时同步更新对应文档。
- **链接必须可解析**：新增或改动文档时确认每个相对链接的目标文件存在；目标文档删除时改为普通文字或指向现行文档。
- **新增文档**：先判断属于哪一层，再扩写现有文档或新建单主题文件，并登记到 [README.md](README.md) 第 3、4 节；执行层每篇只写一个主题。
- **决策背景只进 ADR**：`docs/adr/` 只记为什么这样设计与被否决的方案，其它文档只链接不复述。

## 4. 校验脚本

改动后运行对应脚本；退出码 0 表示通过，1 表示违规，2 表示配置错误（如未找到 Markdown 文档）。

| 脚本 | 触发条件 | 检查内容 |
|---|---|---|
| `python tools/check-docs.py` | 改动 Markdown | 悬空相对链接、禁用路径、反向指针 |
| `python tools/check-isolation.py` | 改动 Java 源码 | 平台隔离与端隔离 |
| `python tools/check-i18n.py` | 改动语言文件 | `en_us.json` 与 `zh_cn.json` 的 key 同步 |
| `powershell -ExecutionPolicy Bypass -File tools/check-ui-kit-boundaries.ps1` | 改动 UI kit | kit 依赖边界 |

禁用路径常量定义在 [check-docs.py](../../tools/check-docs.py) 内，覆盖归档目录，防止现役文档产生归档指针；同一脚本禁止现役文档反向指向仓库根的 agent 指令文件，指针方向只由该文件单向发出。
