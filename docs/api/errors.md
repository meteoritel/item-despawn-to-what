# 错误与状态码

## TL;DR

- 加载期问题用 Issue 表达：严重级决定是否拒载，来源与字段路径决定定位粒度。
- 保存与请求的结果用 RuleSaveStatus 表达：状态码取值集合来自枚举，文案 key 由枚举名推导。
- 客户端只按状态码分支；状态码与文案 key 的新增需要同时改枚举、服务端分支与两端语言文件。

## 适用对象

排查规则为什么没加载、保存为什么失败，或给协议加新状态码的开发者。

## Issue 模型

`Issue` 是一条不可变问题记录，包含严重级、面向人的消息、来源标识与字段路径。`format()` 把四者拼成单行文本，用于日志与回执兜底文案，形如 `[ERROR] origin#fieldPath: message`；来源或路径为空时对应片段省略。

| 组成 | 含义 |
|---|---|
| 严重级 | 决定问题是否阻断加载，取值见 `IssueSeverity` |
| message | 面向人的说明，包含具体键名、取值与期望 |
| origin | 问题归属：来源层名、规则 id 或文件路径 |
| fieldPath | 规则内的定位路径，例如效果槽位与候选结果下的子键 |

`IssueSeverity` 的取值决定是否阻断加载：ERROR 让所在条目或文件被拒载，WARN 只记录、不改变加载结论。新增严重级需要同时改严重级枚举与所有消费它的判定点。

## 收集与来源继承

`IssueCollector` 收集问题并按需派生来源作用域：加载与保存流程为每个文件、每条规则开一个子收集器，写入时自动补齐来源；`issues()` 返回不可变视图，`hasErrors()` 供调用方决定拒载。收集器本身不做线程同步，调用方负责把它限制在单线程阶段内使用，这也是校验流程被拆成主线程步骤的原因。

## 拒载粒度

| 粒度 | 触发条件 | 结果 |
|---|---|---|
| 文件级 | JSON 解析失败、顶层既不是对象也不是数组、文件为空 | 整份文件不参与合并，其余文件继续加载 |
| 条目级 | 字段类型不符、条件树结构非法、语义校验失败、同文件内 id 重复 | 只拒载该条目 |
| 效果与条件叶级 | 类型未注册、参数校验失败、动态引用不存在 | 问题路径定位到具体效果槽位或条件叶，条目整体拒载 |
| 保存整批 | 任一变更校验失败、字节超限、含内容动作的批次版本冲突、写盘失败 | 整批拒绝且不落盘，回执携带问题清单 |
| 快照级 | 无法关联到具体规则的问题 | 作为快照整体问题下发，来源标为运行时，使用加载失败的专门文案 key |

加载失败保留上一版索引：读取目录、合并或重载过程中出现异常时，运行时继续使用旧索引服务，日志记录失败原因。

## 线上问题载体

下发给客户端的问题记录由 `RuleIssue` 表达，字段为严重级、规则 id、来源、字段路径、文案 key、文案参数与兜底文案。严重级常量为 `error` / `warning` / `info`，来源常量为覆盖层、数据包、运行时与网络（见 `RuleIssue` 的 `ORIGIN_*` 常量）；JSON 键名在 record 内以 `KEY_*` 常量维护。

回执中的问题清单有条数与参数长度上限，超出部分被截断，但服务端的拒载判定始终基于未截断的完整结果。

## 状态码

`RuleSaveStatus` 是保存与请求回执的状态码枚举，`id()` 返回枚举名，`messageKey()` 按 `itemdespawntowhat.edit.status.` 加枚举名小写推导，`fromId` 对未知取值返回空值。客户端据此分支，不解析文案。

| 分组 | 代表取值 | 客户端处置 |
|---|---|---|
| 受理成功 | `SUCCESS`、`NO_CHANGES` | 关闭保存模态，按是否已写盘、是否已重载提示；`NO_CHANGES` 表示内容与启用状态都没有实际变化 |
| 请求非法 | `INVALID_REQUEST` | 展示文案参数指出的具体问题，留在编辑器 |
| 校验失败 | `VALIDATION_FAILED` | 展示问题清单，按字段路径定位到草稿 |
| 会话与锁 | `LOCK_BUSY`、`LOCK_NOT_OWNED`、`SESSION_EXPIRED` | 回到未持有状态；锁占用时提示当前持有者 |
| 并发冲突 | `VERSION_CONFLICT` | 拉取最新快照后重新编辑，服务端回传双方版本号；版本比对只覆盖含内容动作的批次，纯启停批次按状态写入结果作答 |
| 落盘与重载 | `WRITE_FAILED`、`SAVED_NOT_RELOADED` | 提示检查日志与备份；已写盘但未生效时提示重载 |
| 环境不可用 | `UNAVAILABLE` | 稍后重试，先确认运行时已就绪；运行时上下文缺失、索引重建或回扫调度失败都回这一码 |
| 用户取消与权限 | `CANCELLED`、`NO_PERMISSION` | 取消是用户动作；权限不足需要提升权限等级 |

完整取值集合以枚举为准。新增状态码的步骤是：加枚举常量、在服务端的返回分支里使用它、在两端语言文件补齐 `itemdespawntowhat.edit.status.<小写名>`、在客户端加分支。仅加枚举而不补文案，会退化为兜底文案展示。

## 保存进度

`RuleSaveProgress` 描述在途保存的阶段、已完成数、总数、当前条目与是否可取消，阶段取值由内部枚举定义，覆盖准备、校验、预备文件、写盘、回滚、读盘、解码、索引、应用与取消。服务端按固定间隔且样本变化时才下发，客户端据此展示进度与决定取消按钮是否可用。

## 文案 key 与语言文件

面向玩家的文案一律走本地化 key，语言文件位于模组资源的 `lang/` 目录，中文与英文两份同步维护。回执同时携带文案 key 与兜底文案：翻译缺失时展示兜底文案，避免出现裸 key。

专门用途的 key 与状态码一起维护：协议版本不一致、快照下发失败、快照超限、问题清单的通用项与解码失败项，各自有固定 key，不要用状态码通用 key 顶替。
