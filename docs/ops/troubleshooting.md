# 故障排查

## TL;DR

- 先分层定位：规则没加载看 Issue 与 `/idtw config validate`，加载了不生效看候选顺序与条件，保存失败看回执状态码。
- 每种症状都对应源码里的确定分支或状态码，按表里的判定线索走，不要凭现象猜测。
- 多数失败不会破坏既有规则：加载失败保留上一版索引，保存失败整批不落盘并保留备份文件。

## 适用对象

接了规则没看到预期转化、编辑器锁打不开、保存回执报错或服务端出现性能抖动的排查者。

## 规则没有生效

| 步骤 | 看什么 | 对应分支 |
|---|---|---|
| 1 | `/idtw config list`、`/idtw config validate` 的输出 | 规则是否被合并进来、校验是否通过 |
| 2 | 日志中的 Issue 行 | WARN 表示条目保留但有可疑内容（例如未知顶层字段）；ERROR 表示条目被拒载 |
| 3 | 规则的 `enabled` 与控制条目 | 覆盖层写了停用控制条目时，基底内容保留但不运行 |
| 4 | 同物品的更高优先级规则 | 候选按 优先级降序、条件复杂度降序、定义序 排序，第一条命中即执行，后面的规则不再判定 |
| 5 | `trigger_after_seconds` 与存活时长 | 自然消失的年龄门槛是秒数换算的 tick，且不超过自然消失前一刻 |
| 6 | `triggers` 是否包含当前消失方式 | 规则未声明消失方式时按自然消失参与判定 |
| 7 | 源物品堆叠数量 | 不足每轮源成本时不选该规则 |
| 8 | 条件求值结果 | 条件不成立时按退避重试到自然消失 |
| 9 | 完整组开组准入 | 邻近统计不足时不支付成本并保留源物品 |

若规则文件本身读不进来，日志会写「数据包重载处理失败，保留上一版规则索引」或列举失败的具体原因，说明运行时仍在使用旧索引；修正文件后执行 `/idtw config reload`。

## 编辑器打不开或锁被占用

| 现象 | 判定 | 处置 |
|---|---|---|
| 打开回执为锁占用 | 回执的文案参数带当前持有者名 | 用 `/idtw config edit-lock status` 查看状态；确认无人操作后用 `edit-lock release` 释放 |
| 查询显示持有者是自己 | 会话仍在，可能是界面关闭但未发送关闭请求 | 等待租约到期，或释放会话 |
| 释放回执提示等待 | 会话处于应用阶段，保存收尾前不释放 | 等保存回执后再释放 |
| 回执为环境不可用 | 运行时未就绪：覆盖层根目录或类型注册表不可用 | 检查启动日志中的降级信息，修正后重启服务端 |
| 回执为请求非法且带协议版本文案 | 客户端与服务端协议版本不同 | 两端使用同一版本模组 |

编辑权限按单人存档或权限等级判定；权限不足时请求被直接拒绝，不会进入取锁流程。

## 保存失败

保存回执只按状态码分支，逐类排查如下：

| 回执 | 判定线索 | 处置 |
|---|---|---|
| 版本冲突 | 服务端回传双方版本号 | 刷新快照后重新编辑；不要重复提交同一批变更 |
| 校验失败 | 回执携带问题清单，字段路径指向具体候选或效果 | 按路径修草稿；保存是整批语义，任一条错都不会落盘 |
| 请求非法 | 文案参数指明具体入口，例如操作标识为空、分片形状非法、变更集超限、已有保存在途 | 按参数修正请求；在途保存结束时再提交 |
| 环境不可用 | 覆盖层工作被判定为不可用 | 检查日志中覆盖层恢复与后台停滞相关记录 |
| 落盘失败 | 问题清单里有整批保存失败的说明；伴随备份文件提示时说明部分文件回滚失败 | 用 `.bak` 备份恢复并检查日志 |
| 已写盘未重载 | 文件已替换成功，但运行时索引未发布 | 执行一次重载；日志会记录重载失败原因 |
| 会话失效或失去锁 | 心跳超时、确认窗口超时、被管理员释放或权限变更 | 重新打开编辑器 |

写入阶段有几条确定的拒绝分支，日志文案可直接定位：覆盖层文件在准备保存时被外部修改、新增规则的目标文件已被占用、规则 id 含非法路径段或越过 `rules` 目录、路径经过符号链接。修正文件现场后重新提交即可。

## 保存长时间无回执

- 保存是跨 tick 的后台任务，进度按固定间隔且内容变化时下发；界面停在某一阶段但仍有进度更新属正常。
- 后台文件工作长时间没有进展时，任务的失败原因会写为覆盖层后台工作长时间无进展、等待文件调用退出；此时回执在收尾后给出，不要重复提交。
- 保存期间同步类命令会直接回「保存进行中」的提示，等回执后再执行。
- 取消请求只发出信号：回滚完成前独占锁保持，终态回执仍由服务端给出；阶段已经进入应用时取消不会生效。

## 启动或重载时规则加载报错

| 日志线索 | 含义 | 处置 |
|---|---|---|
| 列举覆盖层规则文件失败，保留现有规则 | 覆盖层目录无法遍历 | 检查目录权限与路径，修正后重载 |
| 列举数据包规则文件失败，保留现有规则 | 数据包资源枚举失败 | 检查数据包完整性与资源管理器状态 |
| JSON 解析失败 | 该文件整体不参与合并 | 修正该文件 JSON |
| 条件树深度或节点数超出上限 | 条件表达式规模超过解码预算 | 拆分条件或改写为等价的小树 |
| 规则文件顶层必须是规则对象或规则数组 | 文件形状不对 | 改为对象或数组 |
| 同文件内规则 id 重复 | 数组中同 id 出现多次 | 合并为一条 |
| 控制条目只识别 id 与控制键 | 控制条目带了其它字段 | 删掉多余字段 |
| 运行时启动失败，已降级为未启动状态 | 引导阶段失败，规则转换与编辑功能本轮不可用 | 按日志根因修复后重启，世界仍可加载 |

无法获取数据包优先级表时只在层内退化为按文件路径排序，加载继续进行。

## 客户端界面异常

| 现象 | 判定 | 处置 |
|---|---|---|
| 打开编辑界面后列表一直空 | 首份快照尚未到达，或快照装配失败 | 看日志与回执：快照为空时回环境不可用并带快照失败文案；稍后重试或主动刷新 |
| 来源分层内容打不开 | 来源视图返回环境不可用，说明快照索引尚未就绪；返回请求非法说明规则 id 不存在 | 先取到快照再查看来源 |
| 大快照或来源视图加载中断 | 分片超时无进展时客户端缓冲重置 | 重新请求；检查网络抖动 |
| 提交后界面停在应用阶段 | 保存仍在推进或已取消但未收尾 | 看进度是否更新；取消后等终态回执 |

## 分片与网络相关失败

| 现象 | 判定 | 处置 |
|---|---|---|
| 提交超大变更集回请求非法 | 分片收齐后总量超过变更集上限 | 精简变更或分批保存 |
| 单片被拒 | 单片文本超过单分片字节上限，或下标、总数、传输标识不合法 | 客户端按限额重新切分 |
| 传输被丢弃 | 同一玩家的在途传输数超过上限时会淘汰最早一批，或超过传输超时 | 避免并发提交多个大变更集 |
| 整包提交回请求非法而不是断开连接 | 整包只超出网络余量时服务端仍能回执 | 按回执修正请求 |

限额常量的定义位置见[编辑协议契约](../api/edit-protocol.md)。

## 性能抖动

| 现象 | 判定 | 处置 |
|---|---|---|
| 转化明显延迟 | 每 tick 共享预算较小，检查与效果被摊到后续 tick | 调大 tick 预算或每 tick 工作量上限，重启服务端生效 |
| 条件不满足的物品迟迟不再判定 | 失败退避按检查间隔翻倍，到退避上限封顶 | 缩小检查间隔或退避上限，注意会影响整体开销 |
| 效果堆积、条件检查变慢 | 效果类工作量单独限额偏小 | 调整效果类每 tick 工作量 |
| 转化集中爆发 | 到期检查的平滑窗口过大，检查挤在少数 tick | 调整平滑窗口与派发批量 |
| 开组失败但源物品还在 | 邻近容量阈值不足，属于准入判定而非性能问题 | 调整邻近阈值或清理区域 |
| 日志量异常增大 | 常规日志开关被打开 | 关闭常规日志；调试场景的准备预算是独立项，不占用常规 tick 预算 |
